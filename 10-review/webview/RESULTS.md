## 三、三个缺失项的处置判定

只列真正出现过的缺失。每一条都要回答「有没有第二条路」——
这是被真机数据纠正过的方法论：**「探针说这一项不支持」不等于「这个能力在本库里没有效果」**。

| 缺失项 | 出现在 | 处置 | 依据 |
|---|---|---|---|
| `scrollbar-width` | B、E | **可接受降级** | `01-tokens/scrollbar.css` 同时写了 `::-webkit-scrollbar` 伪元素族。B 是 Chromium 内核，E 是 Chromium 97，私有实现都在 ⇒ 观感可接受 |
| `dvh` | E | **可接受降级** | `page.css` 先写 `100vh` 再写 `100dvh`。老内核丢弃后者、保留前者 ⇒ 高度仍在，只是不随地址栏收缩 |
| `@layer` | E | 🔴 **阻塞项，未处置** | 不支持时**整层规则被丢弃**（不是层序错，是那一层样式全没）。本库**目前还没有使用** `@layer`，所以现在不受影响；但这条数据是「不能无条件切层」的唯一依据 |
| 原生 Popover | E | **与本库无关** | 本库的 popover 是自研类名 `.popover` + `data-open`。实测 `grep 'showPopover(' / 'popover=' / '[popover]'` 全无命中 |

⇒ 真正影响使用的缺失是 **0 项**：`scrollbar-width` 和 `dvh` 都有第二条路，`@layer` 与 Popover 本库没用。
但 **E 那一行仍然是阻塞切层的证据** —— 这两件事必须分开说，否则会把"现在能用"误读成"以后随便切层"。

## 四、怎么自己复核一行

不用相信我，三步就能验：

```bash
# 1. 取该行的完整 UA（记录表的「UA」列，一条长字符串）
#    注意：身份标识已脱敏成 <已脱敏>，技术字段完整

# 2. 在目标设备上打开探针页
#    局域网：仓库根目录起静态服务，手机访问 http://<内网地址>:<端口>/10-review/webview/capability-probe.html
#    或直接把 capability-probe.html 拷到手机打开（自包含，不依赖网络）

# 3. 比对两样东西
#    ① 页面顶部显示的 UA 与表里的 UA 是否同族同版本
#    ② 页面汇总行「支持 N / 15」与表里的「结果」列是否一致
#    逐项差异看页面列出的缺失项，应与「缺失能力」列相同
```

**日期锚点**：记录表的「测试日期」一列写的是「见采集所在提交（git log）」——
刷这个文件的历史就能看到每行是哪次提交进来的：

```bash
# 整个文件的录入历史（每一次加了几行，看提交说明）
git log --date=short --pretty="%h %ad %s" -- docs/LAYER-BASELINE.md

# 某一行的归属：拿该行 UA 里的一段唯一串去定位，不依赖行号
git blame --date=short -- docs/LAYER-BASELINE.md | grep 'MQQBrowser/20.6.6'
```

⚠️ 用 UA 片段定位而不是行号：表格前面的段落一改，行号就全漂了，
而 `sed -n '127,133p'` 这种写法会**静默指向别的内容**。锚点要选不会漂的东西。

⚠️ 这里不写字面日期，是**故意**的：本文件在公开仓里，写死日期等于把内部时间线留在仓库里。
提交时间本身就是精确到秒、无法伪造的锚点，比手写的日期更硬。

## 五、下一次实测：原始记录怎么落档

新增一条实测时，除改 `docs/LAYER-BASELINE.md` 的表格，**再做一步**：
把探针页「复制结果」得到的 JSON 原样存成

```
10-review/webview/results/<序号>-<设备>-<入口>.json
```

格式见 [`_TEMPLATE.json`](_TEMPLATE.json)（⚠️ 那是**空模板**，不是数据）。

这样新数据的强度就比现有 7 行高一级：有原始记录，可以重放比对。
**不要求**回头补造前 7 行的 JSON —— 造出来的东西不是证据。
