响应式：流体管尺寸，断点管结构

把浏览器窗口拖窄看左边那根读数条。 注意最后一项：按钮高度不变 —— UI 尺寸不参与流体， 变了会让控件在不同屏幕下大小不一、布局抖动。

一、该流体的：字号与间距

这段正文的字号、上下间距、容器内边距都在随视口连续变化， 中间没有任何断点跳变。这就是 clamp() 的意义 —— 尺寸问题用流体一次解决，不需要在每个断点里重复写一遍。

第二段用来说明另一件事：clamp() 的上下限用的是 rem 不是 px。 所以当你把浏览器默认字号调大（或页面缩放到 200%）时， 文字会跟着一起变大 —— 如果用 px 锁死上下限，用户放到 200% 也涨不上去， 这在 WCAG 1.4.4 里是不通过的。

二、不该流体的：控件尺寸

拖窄窗口——它们不会跟着变小

判据很简单：这个值变了会不会导致"控件大小跟着变"？会 → 不要流体。 `--fs-xs` / `--fs-sm`（UI 文本）和 `--sp-1`~`--sp-3`（小间距）都属这一类。

五、断点在这里

断点只留给"必须换结构"的地方。本页的断点只有一个用途： 读数条在窄屏换行。

断点定义在 tokens.css：30rem / 48rem / 64rem / 80rem （480 / 768 / 1024 / 1280px）。 用 rem 不用 px —— 用户调大字号时断点跟着变，这才是对的。

🔴 但 clamp() 和 CSS 变量都不能写进 media query 条件， 所以 @media (min-width: 48rem) 里的数值仍然是字面值 —— 令牌只是"文档与计算的单一出处"。
