## 三组令牌，三条不同的规则

| 组 | 规则 | 为什么 |
|---|---|---|
| **色** | **全部必须过对比度门禁** | 无对比度的颜色等于没有 |
| **字号** | 标题/正文流体，**UI 文本固定** | UI 字号参与控件尺寸，流体化会抖动 |
| **间距** | 大值流体，小值固定 | 同上 |

🔴 每档的取值与理由都写在下面，**改之前先读这一节**。

## 字号：流体与固定的分工

```css
--fs-xs:   0.75rem;                    /* 12px 固定：辅助文字 */
--fs-sm:   0.875rem;                   /* 14px 固定：UI 文本 */
--fs-base: clamp(1rem, 0.95rem + 0.3vw, 1.125rem);      /* 16 → 18px */
--fs-md:   clamp(1.125rem, 1.05rem + 0.5vw, 1.3125rem); /* 18 → 21px */
--fs-lg:   clamp(1.3125rem, 1.2rem + 0.7vw, 1.5rem);    /* 21 → 24px */
--fs-xl:   clamp(1.5rem, 1.3rem + 1.2vw, 1.875rem);     /* 24 → 30px */
--fs-2xl:  clamp(1.75rem, 1.45rem + 1.8vw, 2.5rem);     /* 28 → 40px */
```

### 两条硬规则

**1. `clamp()` 的上下限必须用 rem，绝不用 px。**
px 上下限不尊重"用户把浏览器字号调大"的设置——下限会锁死，放到 200% 也涨不上去。

**2. UI 文本（`--fs-xs` / `--fs-sm`）不流体。**
它们是**控件尺寸的一部分**。流体会让按钮和输入框在不同屏幕下大小不一、布局抖动。

### 验收判据（WCAG 1.4.4）

> 只要 **MAX ≤ 2.5 × MIN**，就一定通过 resize-text 检查。

本库最大比值 = 2.5 ÷ 1.75 = **1.43**，安全。

### 🔴 硬下限：表单字号 ≥ 16px

`input` 的字号**不能**低于 16px。iOS Safari 在小于 16px 时会自动放大整个页面
**且不缩回**。这是硬约束，不是审美。

## 间距：大值流体

```css
--sp-1: 4px;  --sp-2: 8px;  --sp-3: 12px;         /* 固定 */
--sp-4: clamp(1rem, 0.95rem + 0.3vw, 1.25rem);      /* 16 → 20px */
--sp-5: clamp(1.25rem, 1.15rem + 0.7vw, 1.75rem);   /* 20 → 28px */
--sp-6: clamp(1.5rem, 1.3rem + 1.2vw, 2.25rem);     /* 24 → 36px */
--sp-7: clamp(2rem, 1.7rem + 1.8vw, 3.5rem);        /* 32 → 56px */
--sp-8: clamp(2.5rem, 2.1rem + 2.4vw, 4.5rem);     /* 40 → 72px */
```

**判据**：
> 这个值变了会不会导致"控件大小跟着变"？会 → **不要**流体。

## 断点令牌

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bp-sm` | 30rem (480px) | 大手机 / 小平板 |
| `--bp-md` | 48rem (768px) | 平板 |
| `--bp-lg` | 64rem (1024px) | 小笔记本 |
| `--bp-xl` | 80rem (1280px) | 桌面 |

🔴 **断点用 rem 不用 px** —— 用户调大字号时断点跟着变，这才是对的。

🔴 **CSS 变量不能用在 media query 条件里**，所以写的时候仍要字面值
（`@media (min-width: 48rem)`，不是 `var(--bp-md)`）。
令牌的作用是：给流体计算提供锚点、给脚本查询、让"我们有几个断点"有唯一答案。

## 两份机器可读导出（给不同胃口的工具）

| 文件 | 形状 | 喂给谁 |
|---|---|---|
| `ai/tokens.json` | DTCG 草案：键名带 `--`，字段带 `$`（`$value` / `$type`） | 想**读**令牌的人 / 认 DTCG 的工具 |
| `ai/tokens.tree.json` | 分层：键名不带 `--`，字段不带 `$`（`value` / `type`） | **Style Dictionary / Figma Tokens（Tokens Studio）** |

为什么要两份：**`$value` 和 `value` 是不兼容的两套约定**，
同一个文件喂不进两类工具。`tokens.tree.json` 的 `index` 段把两种键名互相对应
（`--paper` ↔ `color/paper`）。

命令行可直接查：

```bash
node ai/cli.js tokens [--set=light|dark]        # 第一种
node ai/cli.js tree   [--set=light|dark] [--cat=color]   # 第二种
```

⚠️ 第二份是**生成物**，它的正确性不是靠"再生成一遍"保证的 ——
`token-tree-gate.py` 判据 ⑤ 会把每一个名字、每一个值拿到**真浏览器**里，
用 Chrome 自己的 CSS 解析器（CSSOM）重新读一遍再比。

现在 5 个，只能降不能升）。它们不是死代码 —— 是**阶梯的档位**和**给脚本读的常量**，
你写自己的页面时可以直接引用。

| `--bp-sm` / `--bp-lg` / `--bp-xl` | 见上表 | 断点**物理上不可能**被 `var()` 引用（进不了 media query 条件） |

>
> ⚠️ 这一节里的**任何** `--` 开头字符串都会被 `token-audience-gate.py` 当作名单项，

## 页面骨架 `page.css`（选配）

`tokens.css` 管**值**，`typography.css` 管**辅助文字**，`page.css` 管**页面框**：
页面底色/字色/安全区内边距、内容列宽、标题阶梯、行内代码、说明块、演示块。

**只在写了 `class="page"` 的页面上生效**（不写就不生效，对宿主零副作用）。

要改全局观感，改这几个令牌就够了 —— 不要在页面里再写一遍：

| 令牌 | 值 | 管什么 |
|---|---|---|
| `--measure-page` | `52rem` | 内容列宽（所有 `.wrap` 一起变） |
| `--tracking-title` | `-0.02em` | 标题字距 |
| `--fs-2xl` | 见字号表 | 一级标题字号 |
| `--sp-6` / `--sp-4` | 见间距表 | 页面框的上下 / 左右内边距 |
| `--measure-prose` | 见下 | `.wrap--prose`（长文窄列） |

`--measure-page` 的来历：收编之前 33 个页面写了 16 种列宽
（680 / 720 / 760 / 800 / 820 / 860 / 900 px，以及 42 / 44 / 46 / 52 rem 和 72ch），
彼此**没有语义差别**，纯粹是每次手敲随手写的。取众数 820px，落成干净的 `52rem`。

⚠️ 页面里重写 `body` / `h1` / `h2` / `.wrap` / `code` 等
**不会报错但也不会生效**（被 `.page` 前缀的定义以更高特异性静默盖掉，
成为死声明）⇒ `05-audit/shell-gate.py` 会拦住它。
