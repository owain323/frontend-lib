### 🔴 记一条方法教训

**npm registry 的 `unpackedSize` ≠ 浏览器实际加载体积，差 10 倍。**

- `motion` 显示 741 KB，实际直引 `dist/motion.min.js` 只有 **144 KB**
- `auto-animate` 显示 58 KB，实际只有 **8 KB**

查真实体积的正确姿势：

```bash
# 1) 拿真实入口文件
curl -s "https://data.jsdelivr.com/v1/packages/npm/<pkg>@<ver>/entrypoints"
# 2) 看真实字节数
curl -sI "https://cdn.jsdelivr.net/npm/<pkg>@<ver>/<file>" | grep -i content-length
```

## 新增：图标素材库（2026-10-03 核实）

采用的方案：**引库打底 + 自画签名图标**。
核实结论如下（**ISC 是本库目前遇到的协议里最宽松的**）：

### Lucide（打底用）

| 项 | 内容 |
|---|---|
| **协议** | **ISC License** —— 可自由使用/编辑/再分发，**商用无需署名** |
| 格式 | SVG（矢量，任意尺寸不糊） |
| 规格 | 24×24 网格 · **2px 描边** · 圆角端点 |
| 特性 | `absoluteStrokeWidth` —— 从 24px 到 64px 线宽视觉一致 |
| 维护 | 活跃（Feather Icons 的社区分支，Feather 本体是 MIT）|
| 风格 | 线性、克制 —— 与本库的"少装饰"主张一致 |

🔴 **一个我此前的错误判断，已修正**：
> 我说过"引图标库会破坏零外部资产与精简档（某项目）"。

**错的** —— **内联 SVG 仍然是零外部请求**：
把 `<svg>` 直接写进 HTML 就行，不下载字体、不请求图片。
⇒ **Lucide 可以同时服务 A / B / C 三档**，不是"只能给现代站点用"。

⚠️ **使用纪律**：
- **只取需要的图标**（不要整库引，1500 个图标塞进一个页面毫无意义）
- **一律内联 SVG**，不引图标字体（字体文件大、会 FOUT、且违反零外部资产）
- **描边宽度跟随文字大小**（`stroke-width` 用 `currentColor` 联动的相对值，
  避免图标在大字旁边显得过细）
- **入库前逐个看**，不要盲信"社区维护"就是质量统一

### 自画签名图标（待做）

这样混用时看不出接缝。目标：一眼能认出是"这个库做的"。
