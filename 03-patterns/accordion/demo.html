结构要求（APG 原文）

heading 包住 button，不是 button 套 heading：

<h3><button aria-expanded="true">标题</button></h3>

APG 原文："place the heading tag around the button, not inside it, as this would prevent some screen readers (such as VoiceOver and TalkBack) from reading it." 写反了 VoiceOver / TalkBack 读不出标题。

键盘（APG 原文）

Enter / Space 切换 —— 但本组件没有写 keydown 监听

因为原生 <button> 本身就响应这两个键并触发 click —— 写了反而双触发（keydown 切一次、click 又切一次）。 这是「用原生控件」的又一处收益：无障碍行为免费且必然正确。

⚠️ 本组件故意没有方向键 / Home / End。 APG 明确写："arrow / Home / End key navigation is no longer part of the APG Accordion keyboard interaction." 那是 tabs 的契约（roving tabindex）—— 照抄给 accordion 是把两个模式混了。

role="region" 的数量上限

APG 警告：超过约 6 个可同时展开的面板时，给每个 panel 加 role="region" 会造成 "landmark region proliferation"（地标泛滥）—— 读屏用户的地标列表会被几十个「分区」淹没。 ⇒ 面板数 > 6 时不要加，本组件用 accordion--many 关闭它。

反例

反例：用 div 当 trigger

<div class="accordion__trigger"> 键盘上 Tab 不到、 也不响应 Enter/Space。APG 要求 header 里是 role="button" 的元素，用原生 <button> 最省事也最可靠。

反例：折叠时只用 max-height: 0

内容在无障碍树里仍然存在 —— 读屏会念出「折叠」区域里的全部文字， 键盘也能 Tab 进去。必须用 hidden 或 display:none，让它真正离开无障碍树。
