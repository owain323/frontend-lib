## 一、校验时机（本组件最关键的判断）

🔴 **不要在 `oninput` 时报错。**

用户刚敲下 `1`，字段就变红——但 `1` 可能是合法的中间状态。
打到一半满屏红字，用户不知道自己哪里错了，也不敢继续打，**甚至放弃填表**。这是纯噪音。

**三层时机：**

| 时机 | 行为 |
|---|---|
| `onblur` | 失焦时校验一次（用户已经输完一段了） |
| 之后才实时 | 字段"脏"过之后（用户回来改）才实时提示 |
| `onsubmit` | 全量校验，并弹出错误汇总 |

`demo.html` 第一屏就是这两种做法的并排对比，都试着打几个字。

### 刻意不用 `:has()`

第一版用了 `:has(.field__input:focus)` 来控制错误显隐，**是错的**：

1. 把"何时校验"这个**逻辑**硬塞进样式层，行为不可测
2. `:has()` 属 CSS Level 4，兼容性不稳 —— **某项目 上的 WebView 版本不确定，精简档 不能冒这个险**

改成 JS 加 `.is-dirty` 类，CSS 只认这个类。

## 二、错误汇总（提交失败时必做）

WCAG **3.3.1 错误识别** + **3.3.3 错误建议**的落点。

**为什么必须有**：12 个字段错 3 个，错误分散在各字段下方时，用户要上下扫、自己数"还错几个"、猜"上面那个是不是也错了"。汇总一次说清三件事：**有几处错了 / 分别是哪里 / 怎么改**。

汇总里每条用 `<a href="#字段id">`：

- 天然支持键盘
- 能"复制链接"给别人
- 用 `div onclick` 的话键盘不可达

---

## 三、焦点管理（最容易漏）

| 时机 | 焦点去哪 | 不做的后果 |
|---|---|---|
| 提交失败 | 移到**错误汇总**上 | 焦点留在提交按钮，用户按 Enter 又提交一次 |
| 提交成功 | 移到**成功提示**上 | 同上，会重复提交 |

汇总要 `role="alert"` + `tabindex="-1"`，否则屏幕阅读器不知道页面出现了新东西。

## 四、错误文案：给建议，不给判断

```
❌ 格式错误 / 非法输入 / 值不合法
✅ 金额最多两位小数，例如 12.34
✅ 请填写公司名称，2 到 40 个字
✅ 这个日期在未来，请检查
```

3.3.3 要求给修正建议。"格式错误"用户读完还是不知道该改成什么。
**每条都要具体、可执行，最好带一个正例。**

### 🔴 提示必须与**实际那一种错误**对应（分层校验）

实测的真实 bug：金额输入框里输入 `1111aaa`（**含英文字母**），
弹出的提示却是「最多两位小数，例如 12.34」。

**根因不是文案写得不好，是校验只写了一条正则 + 一句固定提示**：

```js
var ok = /^\d+(\.\d{1,2})?$/.test(v);
e.textContent = v === '' ? '金额不能为空' : '最多两位小数，例如 12.34';
```

于是 `1111aaa`、`abc`、`1.2.3`、`.5`……**全都得到同一句提示**。
用户输入字母却被告知小数位，**提示与实际错误完全对不上**，
唯一的效果是让他反复猜。

**正确做法：分层判断，顺序从根本到细节。**

| 层 | 检查 | 提示 |
|---|---|---|
| 1 | 为空 | 金额不能为空 |
| 2 | **含非数字字符** | 只能输入数字，`a` 不是有效字符 |
| 3 | 小数点超过一个 | 只能有一个小数点 |
| 4 | 小数位超过两位 | 最多两位小数，例如 12.34 |
| 5 | 兜底（半截输入） | 格式不对，示例：12.34 |

🔴 **顺序不能乱**：含字母时**先说"只能输入数字"**，而不是先说小数位 ——
用户要先解决"有字母"这个障碍，才谈得上小数位。先报后面的错误等于没报。

**能指名道姓就别泛泛而谈**：`a 不是有效字符` 比 `包含无效字符` 更有用，
用户立刻知道要删哪一个。

## 五、无障碍要点

1. 错误汇总：`role="alert"` + 提交后焦点移到它
2. 汇总条目：`<a href="#id">`，不要 `div onclick`
3. 错误文案：`role="alert"`（动态出现时读出）+ `aria-describedby`（聚焦时听到）
4. 字段加 `aria-invalid="true"`
5. **异步校验时不要禁用输入框** —— 用户会以为不能打字了。保持可输入，旁边给小提示

---

## 反例

- ❌ **oninput 实时报错** —— 噪音，会让人放弃填表
- ❌ **没有错误汇总** —— WCAG 3.3.1 要求错误可识别
- ❌ **汇总条目用 `div onclick`** —— 键盘不可达
- ❌ **提交失败/成功后焦点不动** —— 会重复提交
- ❌ **异步校验时禁用输入框** —— 用户以为不能打字了
- ❌ **错误文案只说"格式错误"** —— 3.3.3 要求给建议
- ❌ **用 `:has()` 做校验时机控制** —— 逻辑塞进样式层，不可测；且兼容性不稳

### 库内两处反模式钩子

`form-validation.css` 末尾的反模式清单里，**刻意用注释写了几条真实的错误写法**
（`oninput` 报错、没有汇总等）。`states.py` 的反模式扫描已改成在去注释后的文本上跑，
所以那些注释**不会**被误判成真代码。改这个脚本时别把这个修复弄丢了。
