# 容器四态：empty / loading / error / success

| 字段 | 内容 |
|---|---|
| **来源** | 原创 |
| **实测** | 演示见 `demo.html`（含 300ms 延迟的真实效果）；色值对比度沿用 tokens 已测值 |
| **适用** | 精简档 / B / C，纯 CSS（延迟显示需 ~10 行 JS） |
| **依赖** | `01-tokens/tokens.css` `02-primitives/button/button.css`（分段控件用 `.btn`）|
| **门禁** | ⚠️ **无自动门禁** —— 见下方"验收清单" |

---

## 四态各自必须有什么

| 态 | 必须 | 不做会怎样 |
|---|---|---|
| **empty** | 说明**为什么空** + 下一步动作 | "暂无数据"四个字把用户卡死 |
| **loading** | "在动"的指示（spinner 或骨架屏） | 用户以为加载已结束且结果为空 |
| **error** | 说清出了什么事 + **重试出口** | 死路，只能刷新页面（而刷新常常解决不了） |
| **success** | 结果摘要 + 下一步出口 | 用户不知道接下来去哪 |

🔴 **error 的可恢复性是硬要求。** 只写"出错了"是死路。
而且刷新往往解决不了问题（比如参数错了、文件格式不对）——必须给"改了再试"的路径。

---

## 骨架屏 vs spinner：按结构是否已知选

| | 骨架屏 | spinner |
|---|---|---|
| 何时用 | **结构已知**——知道会来"标题+三行+一张图" | **结构未知**——不知道会来什么 |
| 价值 | 内容到位时不跳动 | 不撒谎 |
| 用错的后果 | 结构不一致 → 内容到位时布局剧烈跳动 | 结构已知时显得慢 |

🔴 **别在结构未知时用骨架屏**——那画出来的结构是在撒谎。

骨架屏必须标 `aria-hidden="true"`，否则屏幕阅读器会把它读成一堆无意义色块。

---

## 300ms 延迟（需要 JS，约 10 行）

请求在 300ms 内返回时**不要显示加载态**。骨架屏闪一下比不显示更糟——那是一次无意义的闪烁，反而让人觉得卡。

```js
let t = setTimeout(() => showLoading(), 300);   // 300ms 后才显示
fetch(...).then(r => { clearTimeout(t); showResult(r); });
```

`demo.html` 里有两个按钮可以直接对比：120ms 的那个完全不显示加载态，1.4s 的才显示。

## reduced-motion 下：两个动画，处理相反

这是本组件最值得记住的一条。判断依据是**去掉后是否损失信息**：

| 动画 | 处理 | 理由 |
|---|---|---|
| **spinner** | **保留**，放慢到 1.2s | 停了用户会以为页面卡死。原地旋转不属于"大幅位移" |
| **骨架屏扫光** | **停止**，保留静态占位 | 静态色块仍传达"内容正在来"，不损失信息；而扫光正是横向位移 |

同样是"加载中的动画"，一个保留一个去掉。

---

## 无障碍三条

1. loading 容器标 `aria-busy="true"`
2. error / success 动态出现时用 `role="alert"` 或 `aria-live="polite"`——否则屏幕阅读器用户不知道状态变了
3. 骨架屏标 `aria-hidden="true"`

---

## 反例

- ❌ **empty 和 loading 用同一个样式** —— 用户分不清是"在加载"还是"真没有"
- ❌ **empty 态不放动作按钮** —— 把用户卡死
- ❌ **error 态没有重试出口** —— 死路
- ❌ **结构未知时用骨架屏** —— 撒谎，且内容到位时跳动
- ❌ **请求 <300ms 也显示骨架屏** —— 闪一下更糟
- ❌ **把普通操作的成功做成整页 success** —— 成功是过渡态，用 button 的 `.is-success`（1.2s 自动消失）
- ❌ **把技术细节（错误码、堆栈）写进主文案** —— 用户要看的是"我该怎么办"。细节放 `.state__detail` 折叠

## 验收清单（替代自动门禁）

`states.py` 不检查容器态——它检查的是交互元素，容器不是。
所以这一项**目前靠人工检查**，按下面七条过：

1. 每个会承载数据的容器，是否都写了 empty 态？
2. empty 态有没有说明"为什么是空的"？（"还没有导入任何公司" > "暂无数据"）
3. empty 态有没有动作按钮？
4. loading 是骨架屏还是 spinner？选择依据是不是"结构是否已知"？
5. error 态有没有重试出口？
6. 有没有做 300ms 延迟？
7. 骨架屏有没有 `aria-hidden`？loading 容器有没有 `aria-busy`？

🔴 为什么不做自动门禁：启发式只能查"有没有 empty 这个类"，查不出"empty 态有没有动作按钮"——
那才是真正容易漏的。做一个只能查到皮毛的脚本，会给出假绿。**不检查比假绿诚实。**

## 钩子（CSS 有，JS 需你自己加类）

| 类 | 作用 | 谁来加 |
|---|---|---|
| `.state--delayed` + `.is-shown` | 延迟 300ms 再显示骨架屏，避免快速返回时"闪一下" | **你**：定时器到点加 `.is-shown` |
| `.field__input.is-valid` | 输入框"校验通过"态 | **你**：校验通过时加 `.is-valid` |

⚠️ **本库不提供 JS 实现** —— 这两个是留给复用者的钩子。
CSS 侧已经备好，JS 侧要自己写。写错了不会报错（类没加就是默认态），
所以**要自己验**。
