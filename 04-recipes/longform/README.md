## 品味取舍（依据 `00-charter/05-品味规范.md`）

| 决定 | 具体做法 | 为什么 |
|---|---|---|
| **唯一视觉焦点** | 标题 `max-width: 15ch`，必然换三行 | 眯眼时第一眼必须落在某处 |
| **不对称** | 目录 13rem + 正文 68ch，两列不等宽 | 均一不产生节奏 |
| **段落零框** | 只给代码块和引文加框 | 满屏卡片 = slop 的第一特征 |
| **衬线标题 + 无衬线正文** | Georgia/Songti + PingFang | 衬线给编辑感与严肃感，正文无衬线保证可读 |
| **标题 `font-weight: 400`** | 靠字号建层级，不靠粗体 | 衬线体的粗体很丑 |
| **通栏禁令** | 正文一律 `max-width: 62ch` | 行长超过 75ch 阅读就开始跳行 |
| **真实数据** | AGC 内存表、861k 记录等 | 模板生成器 2 秒做不出来的东西 |

## 几个具体做法

**目录高亮用 `IntersectionObserver`，但必须有降级路径。**
精简档 的 WebView 版本不确定，所以：

```js
if (!('IntersectionObserver' in window)) { return; }  // 降级：不高亮，功能不受损
```

不支持时目录仍然是普通链接，**可用性不受影响**。

**跳到主内容链接**：键盘用户第一个 Tab 就能跳过 5 项目录。

**代码块 `overflow-x: auto` 而不是让页面撑破** —— 窄屏时横向滚动在代码块内部，不影响整页布局。

**证据分级标记**（`A/B/C`）：考古文章最容易出问题的是数字。
本文中标 `C` 的数字**只用于说明结构，不用于支撑论断** —— 这条是编辑纪律，不是免责声明。

## 反例 —— 什么时候不该用它

- ❌ **界面类项目用这个 recipe** —— 它是 68ch 窄栏单栏排版。
  数据看板、工作台需要另一套（密度更高、容器更多）
- ❌ **直接在标准档/C 用它** —— 标准档/C 可以引外部 CSS，不必内联。
  硬内联会让缓存失效
- ❌ **拿它当"排版规范"** —— 它是一篇**具体文章**。
  规则散在 `01-tokens` 和 `00-charter` 里，那些才是可复用的
