# 素材（图标）

> 建立于 · 决定「引库打底 + 自画签名图标」

## 为什么要这一层

之前库只有 CSS 与 JS，**一个图标都没有** ——
凡是"关闭""警告""箭头"都得手写文字或用 emoji（emoji 在不同系统长相不一样，
且无法控制颜色与描边）。

但 评审指出更实际的理由：
> 「如果没有这种资产的话，我们之后干活干起来也是很累的。」

**图标是"资产"**——做过一次就能一直复用，不做则每个项目重复造。

## 两条来源

| 来源 | 协议 | 谁来放 |
|---|---|---|
| **Lucide**（打底） | **ISC**（商用无需署名）| 见下方「需要你提供」|
| **自画签名图标** | 本库自有 | 已画 3 个（见下）|

## 使用纪律

**一律内联 SVG。** 不引图标字体、不引图片文件 —— 这样：

- 零外部请求（**精简档 / 某项目 依然能用**）
- 颜色随 `currentColor` 走，暗色模式自动跟随
- 描边粗细随字号变，不会出现"小图标过粗、大图标过细"

反例（不要这样做）：

```html
<!-- ❌ 引入字体：一个大文件 + FOUT + 违反零外部资产 -->
<link rel="stylesheet" href="//cdn.example.com/icons.css">
<i class="icon icon-close"></i>

<!-- ❌ 引入图片：无法跟随 currentColor，暗色模式下要换图 -->
<img src="close.png" alt="">
```

## 规格（签名图标与 Lucide 完全一致，混用看不出接缝）

```
viewBox   0 0 24 24
width     1em          ← 跟随字号，不是固定 px
height    1em
fill      none
stroke    currentColor
stroke-width  2
stroke-linecap  round
stroke-linejoin round
```

## 签名图标：**暂缓，理由如下**

我画过 3 个（设计令牌 / 版本 / 门禁），**看过的评价**：

> 「这个方块长得像毛毛虫，这个打勾的那种也不知道它到底在表达什么」

⇒ **判断是对的。** 两个硬问题：

1. **语义传达不清** —— 图形是自洽的，但**读不出概念**。
   这不是"再修修线条"能解决的，是**图形语言本身没建立**。
2. **零使用场景** —— 全库没有任何地方引用它们。
   等于三个"没人用的漂亮图标" —— **这本身就是另一种 AI 味**
   （"看起来有产出，其实没有"）。

**已删除。**

🔴 **什么时候再做**：等**真出现一个 Lucide 没有、
而我们又确实需要**的概念时，画那一个 ——
有使用场景的图标才画得出来，脱离场景画只能画出"不明所以"。
在那之前，**先把 Lucide 用起来、把组件补齐**更有价值。
