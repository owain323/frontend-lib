真实的 `npm pack` + `npm install *.tgz` 内容完全干净（`files` 白名单生效）。

⇒ 这条已转成 W2（打包实装冒烟），**确保结论持续成立**，而不是改一个不存在的 bug。

### 顺带修掉的门禁自身假绿

这两条比评审列的更严重 —— **门禁在骗人**：

1. **`es5-gate` 传 `--dir` 时扫 0 个文件，却报 PASS**。
   它自己源码第 98-103 行就写了这个警告，但 `check-all.sh` 一直在传 `--dir`。
   ⇒ 已改回位置参数，现在真扫 53 个文件。
2. **16 个门禁用 `--dir .`，会扫进 `node_modules`**。
   装 TypeScript 后立刻暴露：a11y 报「index.html 缺 lang」，那是第三方文件。
   ⇒ 改为显式列举目录 + 按门禁能力分组。

> **最危险的不是代码有bug，而是治理系统给出错误的绿灯。**

## 二·五、0.4.0 已完成（对标五强后的拔高）

对标 Pico CSS / Radix / Open Props / Web Awesome / Primer，
每一条的「学什么、不学什么、为什么不学」都写在 `BENCHMARK.md`。

| 事项 | 来源 | 判据（怎么算做完） |
|---|---|---|
| `ai/` 机器可读契约 + 由源码生成 + 同步门禁 | Open Props / Web Awesome | 改源码不重新生成 ⇒ 红；注入假组件 ⇒ 拒 |
| Patch API（对语义 ID 的五种操作） | 结构要求 | 非法操作 ⇒ 文档字节级不变 |
| 独立 CLI `node ai/cli.js` | 结构要求 | 不加载任何模型也能跑完八个子命令 |
| Profiles + 组件成熟度 | Primer | strict 下报错数 > creative 下报错数 |
| 能力协商（不按模型名分支） | 结构要求 | 声明不同能力 ⇒ 得到不同可用操作集 |
| 前向兼容 `extensions` | 结构要求 | 旧校验器遇未知扩展只忽略，不判非法 |
| 呈现形态语义移出核心 | 结构要求 | 核心检索呈现类关键词 ⇒ 0 命中 |
| 规范分三层（Invariant / Contract / Guidance） | 架构要求 | 三层职责不重叠；建议层改动不影响门禁 |

| **`is-*` 收敛为 data 属性** | Radix | 全库归零；成熟度按四条判据重判 —— **不是一律 stable**（27 个全 stable 的阶梯没有鉴别力，对标 Primer 六档每档都要有硬判据；现状 20 stable / 7 beta） |
| 级联分层**就绪门控**（不切换） | Web Awesome | 每处 `!important` 都能归类；加第一条 `@layer` 就要基线档 |

⚠️ 级联分层**故意不切**：目标环境是移动 WebView，基线未确认，
切换等于拿使用者的线上页面赌。前提与判据见 `BENCHMARK.md`
「级联分层的决定」一节 —— **写了就算闭环，不是遗留缺口**。

## 四、执行纪律（本轮血泪）

1. **每条门禁都要反向控制** —— 注入坏样本，确认它会红。
   本轮有三道门禁因此暴露自身失效（fixture 写错、假绿、路径解析失败）。
2. **区分「真 bug」与「看起来像 bug」** —— npm 泄漏那条就是误判，
   先实测再动手，否则会改一个不存在的问题。
3. **批量改动后立刻做结构校验** —— JS 语法、CSS 花括号、Python `ast.parse`，
   再逐文件与改前对照，确认没破坏原有结构。
4. **清理项目用脚本不入库** —— 一次性清理脚本用完即删。
5. **提交前跑门禁，推送后验证远端** —— 且要用陌生人视角 `git clone` 一遍。
