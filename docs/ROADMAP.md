## 四、执行纪律（本轮血泪）

1. **每条门禁都要反向控制** —— 注入坏样本，确认它会红。
   本轮有三道门禁因此暴露自身失效（fixture 写错、假绿、路径解析失败）。
2. **区分「真 bug」与「看起来像 bug」** —— npm 泄漏那条就是误判，
   先实测再动手，否则会改一个不存在的问题。
3. **批量改动后立刻做结构校验** —— JS 语法、CSS 花括号、Python `ast.parse`，
   再逐文件与改前对照，确认没破坏原有结构。
4. **清理项目用脚本不入库** —— 一次性清理脚本用完即删。
5. **提交前跑门禁，推送后验证远端** —— 且要用陌生人视角 `git clone` 一遍。
