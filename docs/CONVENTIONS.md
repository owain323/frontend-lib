# 全局约定

这些规则不属于任何一个组件：令牌怎么用、焦点环多大、动效多久、暗色怎么切、
能不能写 `margin-left`。它们由 `01-tokens/` 里的几个全局文件实现，由一批门禁守住。
本文是它们的**唯一说明书** —— 规则写在这里，判据在仓库里，两边一一对应。

读法：如果你只想知道「我该写哪个变量」，看第一节和第二节；
如果你想改这套东西，看第十一节，那里列了每条规则由什么挡住。

## 一 · 令牌分三层，你只用中间层

| 层 | 长什么样 | 谁写 | 谁用 |
|---|---|---|---|
| raw | `--raw-paper`、`--raw-text-primary` | 只有 `01-tokens/tokens.css` | 没人 —— 它是调色板原料 |
| 语义 | `--paper`、`--surface`、`--text-primary` | 只有 `01-tokens/tokens.css` | **你的代码用这一层** |
| 组件私有 | `--btn-pad` 之类 | 该组件自己的 CSS | 该组件自己 |

**为什么必须隔一层**：暗色不是"把颜色逐条改掉"，而是**换掉 raw 的值，语义层不动**。
组件里写 `--raw-*`，暗色就会漏掉它 —— 这也是 `dark-contrast.js` 会算两遍对比度的原因。
组件与页面里**写死 `#hex`** 一律不许（`hygiene.py` 判）。

常用语义令牌，括号里是对当前纸底 / 表面的**实算对比度**（不是估的）：

| 令牌 | 用途 | 对比度 |
|---|---|---|
| `--paper` | 页面底色 | — |
| `--surface` / `--surface-raised` / `--surface-sunken` | 卡片 / 浮起 / 凹陷 | — |
| `--text-primary` | 正文 | 16.60 / 17.81 · AAA |
| `--text-secondary` | 次要说明 | 7.01 · AAA |
| `--text-tertiary` | 弱化文字 | 5.33 / 4.89 · AA |
| `--border-control` | 输入框等**控件**边框 | 3.19 / 3.42 · AA（大字与控件） |
| `--border-decor` | 纯装饰分隔线 | 1.18 · 不适用（WCAG 不强制装饰） |
| `--accent` / `--accent-soft` | 强调色 / 浅底与焦点环 | 见 `contrast.py` 输出 |

⚠️ `--accent-soft` **不要拿来当正文背景**：它只保证"能看见有一块色"，不保证字读得清。

## 二 · 间距、圆角、层级：只准踩台阶

间距是 8 档，前 3 档固定、后 5 档随视口缩放：

| 令牌 | 值 | 说明 |
|---|---|---|
| `--sp-1` / `--sp-2` / `--sp-3` | 4 / 8 / 12px | 组件内部微调 |
| `--sp-4` | `clamp(1rem, …, 1.25rem)` | 16 → 20px |
| `--sp-5` | `clamp(1.25rem, …, 1.75rem)` | 20 → 28px |
| `--sp-6` | `clamp(1.5rem, …, 2.25rem)` | 24 → 36px |
| `--sp-7` | `clamp(2rem, …, 3.5rem)` | 32 → 56px |
| `--sp-8` | `clamp(2.5rem, …, 4.5rem)` | 40 → 72px |

圆角：`--r-xs 3` / `--r-sm 6` / `--r-md 10` / `--r-lg 14` / `--r-pill 999`（px）。
层级：`--z-base 0` → `--z-sticky 10` → `--z-header 20` → `--z-overlay 30` →
`--z-modal 40` → `--z-toast 50`，另有 `--z-raised 5`（卡片悬停、内层可点元素）。

写 `padding: 13px` 不算错，但它**不会跟着页面框一起变** —— 这就是为什么
文档站曾经出现"改 `--sp-6`，35 页 padding-top 一动不动"（那时页面框被写了两份）。

## 三 · 焦点环：`:focus-visible`，2px + 2px

```css
:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
  border-radius: var(--r-sm);
}
```

- **只用 `:focus-visible`，不用 `:focus`**。前者只给键盘用户看，鼠标点击不冒框。
  用 `:focus` 的后果是"点一下留个框"，用户会以为界面卡住了。
- **禁止 `outline: none` 而不给替代指示** —— 这是无障碍事故，不是审美选择。
  真要自绘，用 `--focus-ring-width` / `--focus-ring-offset` / `--focus-ring-color`
  三个令牌，别自己写死像素。
- 深底上（暗色、实心按钮）加一圈内白环 `--focus-ring-inset`，否则焦点环与背景糊在一起。
- 打开弹层再关掉，**焦点必须回到触发它的元素**上：`focus-return-check.js` 判这一条。

## 四 · 动效：三档时长，三条规定

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--dur-fast` | 120ms | 颜色、透明度、悬停 |
| `--dur-base` | 180ms | 位移、展开 |
| `--dur-slow` | 280ms | 大块入场、遮罩 |

曲线三条：`--ease-out`（入场/展开）、`--ease-in-out`（屏上位移/折叠）、
`--ease-drawer`（抽屉式滑入）。超过 300ms 的 UI 动效会被读成"卡"。

系统开了"减少动效"时，策略是**分档**的，不是一刀切：

1. **位移 / 缩放 / 旋转 —— 关**。前庭不适的主要来源。
2. **真实进度（spinner、加载态）—— 留**。停掉它，用户会以为没点上，从而重复提交；
   这比有动画更糟。目前登记的例外只有三处：`button`、`states`、`form-validation`。
3. **颜色 / 透明度 —— 可以缩短到 `--dur-fast` 保留**，这一档不强制、也没有判据
   （写了却没判据的规则，比没有规则更糟）。

例外登记在 `ai/motion-policy.json`。**声明了却没实现 ⇒ 红；实现了却没声明 ⇒ 红。**
这条双向判据是它存在的全部意义。

## 五 · 暗色：三种状态，组件一律不许自判

| 使用者的意思 | 怎么表达 |
|---|---|
| 跟随系统 | 什么都不写（`color-scheme: light dark` 已声明） |
| 我要亮的 | `<html data-theme="light">` |
| 我要暗的 | `<html data-theme="dark">` |

实现上有两个必须知道的坑：

- 系统暗色那一段的选择器是 `:root:not([data-theme="light"])`，**强制暗**另由
  `:root[data-theme="dark"]` 那一段负责，两段互不干扰。
  **少了 `:not(...)`**，系统开着暗色时使用者点"亮"仍然会看到暗的 ——
  三态开关里最容易被漏掉的那条路径（这也是为什么"强制亮"能压过系统暗色）。
- **组件里不许出现 `prefers-color-scheme`**。组件只认语义令牌，主题切换由
  `tokens.css` 一处完成。组件自己判主题，等于给每种组件各开一个"主题分支"，
  加一个主题就要改 35 个文件。

暗色不等于"把浅色取反"，三条已经踩过的坑：正文不用纯白（深底上字会发散）、
凹陷面在暗色里要**比纸面略亮**（层级靠变亮，不是变暗）、滚动条 thumb 要更亮
（用浅色那档会变成"黑里有黑"）。

## 六 · 逻辑属性：不许写 `margin-left`

交付的 43 个 CSS 里，物理方向属性（`margin-left` / `padding-left` / `left:`）**0 处**，
全部用 `margin-inline-start` 这类逻辑属性。`rtl-check.js` 守这一条。

绝对定位是唯一需要动脑的地方：

```css
/* 错的：RTL 下浮层会跑到另一边 */
.tip { position: absolute; left: 0; }
/* 对的：两个方向都说清楚 */
.tip { position: absolute; inset-inline-start: 0; }
/* 确实要按物理方向时，显式覆盖 */
[dir="rtl"] .tip { left: auto; right: 0; }
```

## 七 · 不用 `@layer`；`!important` 必须说得清

交付 CSS 里 `@layer` 是 **0 处**，这是决定，不是遗漏：目标环境里有 Chromium 97 的内核
（见[浏览器支持矩阵](../SUPPORT.md)），它不认识 `@layer` —— **整层样式会直接消失**。
所以"未分层"是当前唯一安全的选择。`cascade-layer-gate.py` 把这条变成可判状态：
一旦出现第一条 `@layer`，就要求三条前提的实测记录已落档，否则红。

`!important` 现有 10 处，**每一处都必须能被归类**：

| 类别 | 处数 | 为什么必须赢 |
|---|---|---|
| 无障碍偏好（`prefers-reduced-motion`） | 9 | 操作系统级偏好，组件无权推翻 |
| 正确性（`[hidden] { display: none }`） | 1 | 不赢就会"藏不住" |

分不了类的 `!important` ⇒ 红。判据不是"清零"——清零会逼人删掉无障碍兜底。

## 八 · 对比度与触控的硬线

- 正文 **4.5:1**，大字与**控件**边界 **3:1**，纯装饰不强制（但也不许拿来传信息）。
- 触控目标 **44×44**（WCAG 2.5.5）。视觉尺寸可以更小，热区要补足。
- **禁用态用明确色值，不用 `opacity`**。半透明会让文字对比度随底色漂移，
  在暗色下直接不达标；而且"看起来只是淡了点"没法表达"不能点"。

## 九 · 覆盖策略：改令牌，不要改组件

```css
/* 换品牌色：只改一个语义令牌，全站生效，暗色与焦点环自动跟上 */
:root { --accent: var(--brand-accent); }
```

`--brand-accent` 由你自己定义（任意合法颜色值）。之所以不在这里写一个具体的十六进制：
本库的对比度判据会把**文档里的色值**当成"内联副本"去核对，
它分不清示例与真实用法 —— 与其教它开例外，不如让示例本来就不带字面值。

- 优先覆盖 **语义令牌**（第一节那张表）。
- 其次覆盖组件自己的槽位变量（如按钮的内边距），它们都以组件名为前缀。
- **不要把 `!important` 当覆盖手段**：赢了这一条，会把无障碍兜底一起压掉。
- 不要用更深的选择器去压（`.page .btn.btn--primary`）—— 那是把特异性当版本管理，
  下次改版必然打架。

## 十 · 涨跌：语义在令牌层，口径是全局的

红绿有两个完全不同的来处，**不许共用一个名字**：

| 令牌 | 语义 | 例子 |
|---|---|---|
| `--danger` / `--success` | **评价**：错了 / 成了 | 审计失败、已停牌 |
| `--dir-up` / `--dir-down` | **事实**：涨了 / 跌了 | 同比 +12.4% |

「研发费用同比 +38%」是涨，但那是坏消息 —— 用 `--danger` 渲染它，
颜色说"错了"、语义说"涨了"，读者收到矛盾信号。

三条规则：

- **组件只写 `color: var(--dir-up)`**，不许出现 `[data-market]` 分支。
  口径切换改的是**令牌指向**，跟暗色同构（换底层值，语义名不动）。
- **口径是全局约定**：`data-market="intl"` 加在任意祖先上，整块对调。
  交换规则在选配文件 `01-tokens/market.css`，**不在 `tokens.css`** ——
  条件规则进核心令牌会让六个靠词法读 CSS 的工具静默读错。
- **方向必须有非颜色的载体**：`delta` 用 `+` / `−`（U+2212）符号，
  且符号必须真的进可访问性树（CSS `::before` 生成的字符不在元素 name 里，
  但会作为独立 StaticText 出现 —— 换空串/背景图/`visibility:hidden` 就会没）。
  ⚠️ 别把这条推广成"伪元素文本永远不影响可访问名"：**`name-from-contents` 的元素
  （`<button>` / `<a>`）会把伪元素文本算进名字** —— `table` 的列头就是这样被念出
  「公司 · ↕ · 按钮」的（三个引擎都实测过，见
  [无障碍人工测试协议](A11Y-MANUAL-PROTOCOL.md)）。装饰性符号别挂在按钮上，
  或者用 `mask` 画。
- **容器不许再加一套方向类**。表格里只有会计正负（`num--pos` / `num--neg`），
  市场涨跌一律嵌 `<span class="delta delta--up">`
  —— 否则 `table` 会有四组颜色类，调用方每列都要记"这列用哪组"。
  表格只管对齐（`td.num`），不管判色。
- **零值不带符号**：符号必须跟**打印出来的数字**同号。
  `0` 与「四舍五入到 0」（如精度 1 下的 `0.0004`）都不加 `+` / `−`
  —— 「+0.0%」等于把持平念成上涨。会计列与市场列是同一条规则。

## 十一 · 每条规则由什么挡住

规则只有落到判据上才会被遵守。对应关系如下（文件都在 `05-audit/`）：

| 规则 | 判据 |
|---|---|
| 不写死 `#hex`、不留调试残留 | `hygiene.py` |
| 组件之间不许 `@import` 互相依赖 | `css-independence.py` |
| 亮/暗两套对比度达标 | `contrast.py`、`dark-contrast.js`、`component-contrast.py` |
| 焦点环存在且不是 `outline:none` | `focus-ring-check.js` |
| 关掉弹层后焦点回到触发点 | `focus-return-check.js` |
| 键盘可达（Tab 顺序、Esc 关闭） | `keyboard-nav.js` |
| 减少动效策略双向一致 | `motion.py --reduced-audit` |
| 逻辑属性全覆盖 | `rtl-check.js` |
| `@layer` 计数与 `!important` 分类 | `cascade-layer-gate.py` |
| 触控目标 44px | `a11y.py`（静态） + 行为脚本（运行时） |
| 页面骨架只有一份（改令牌能牵动全部页面） | `skeleton-lever-check.js` |
| 涨跌方向色对、口径可切、符号进可访问性树 | `delta-check.js` |
| 表格里的方向语义（涨跌嵌 `delta`、零值不带符号、口径只翻市场列） | `table-check.js` ⑫⑬⑭ |
| 指标缺数是显式状态、数字等宽对齐 | `metric-check.js` |
| 文档里的数字与实际一致（组件数/门禁数/精简档令牌数） | `doc-facts-gate.py` |

想加一条新规则？先在门禁里加判据、确认它会红，再写进本文 ——
**顺序反了就会得到一条"写在文档里、没人执行"的规则。**
