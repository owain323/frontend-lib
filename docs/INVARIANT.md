# 不变式（Invariant）

> **这一层里写的不是「给 AI 定的规矩」，是「客观事实」。**
> 因此它**不会**因为模型变强而失效，也不需要"以后放宽"。

---

## 为什么要单独分出这一层

一个真实的架构悖论：

> 今天为了让 AI 少犯错而加的约束，明天可能变成更强的 AI 的天花板。

这个悖论之所以成立，是因为**大多数"约束"其实是给当前模型能力打的补丁**：
模型不会规划 ⇒ 那就规定它必须按步骤走；模型不会看全局 ⇒ 那就禁止它改全局。

模型一旦变强，这些补丁就从"护栏"变成"牢笼"。

**解法不是"以后再说"，是分层。** 只有把「事实」和「补丁」分开，
补丁才能被安全地摘掉，而事实一个字都不用动。

| 层 | 是什么 | 会不会变 | 谁负责 |
|---|---|---|---|
| **Invariant**（本文件） | 客观事实 | **永不变**（除非 CSS 规范变了） | 门禁 |
| **Contract**（`ai/contract.schema.json`） | 版本化的接口约定 | 随版本变，**向后兼容** | 校验器 |
| **Guidance**（`docs/GUIDANCE.md`） | 当前模型下的工作建议 | **随时可变，可整份推翻** | 人 |

⇒ **判断一条内容该放哪层的唯一标准**：
> 如果明天出现一个无限强的模型，这句话还成立吗？
> 成立 ⇒ Invariant。不成立 ⇒ Guidance。
> 是"我们约定好接口长这样" ⇒ Contract。

## 一、作用域类事实

### I-1 裸标签选择器的作用域是**整个文档**

```css
a { color: red }        /* 命中文档里每一个 <a>，无论它属于谁 */
```

这是 CSS 的定义，不是我们的规定。

**推论**：在一个"我们不拥有整个文档"的库里写裸标签选择器，
等价于**修改使用者的页面**。与谁在写这行代码无关，与模型强弱无关。

- 门禁：`bleed-gate.py`
- 已发生的事故：`03-patterns/content/content.css` 曾有 `a { color: var(--accent) }`，
  把宿主全站链接染色。已修。

### I-2 页面级 override 链的复杂度是**单调递增**的

```css
.slide-3 h1 { ... }     /* 第 1 次局部调整 */
.slide-4 h1 { ... }     /* 第 2 次 */
.slide-3 .card h1 { ... }/* 发现冲突，加码 */
```

每加一层特异性，就**只能再加一层**来覆盖它。
这不是"AI 容易犯的错"，是**特异性机制的必然结果**。

**推论**：修组件，不要修页面。这条在任何人手里都成立。

### I-3 未分层样式**永远**赢过已分层样式

`@layer` 的层序优先于选择器特异性。
（这也是为什么 Web Awesome 把全局样式分层——让使用者的 CSS 自动赢，不需要 `!important`。）

- 本库未使用 `@layer`。理由、切换前提与就绪判据见 `docs/BENCHMARK.md` 的「级联分层的决定」一节。

### I-4 inline style 的优先级高于**一切**样式表

`element.style.setProperty('--surface', x)` 会压掉使用者样式表里的 `--surface`，
使用者只能再加 `!important` 反击。

- 过去的代价：强制暗色曾靠 JS 往 `:root` 写 30 条 inline 属性实现，
  等于把整个配色层抬到样式表之上。
- 现已消除：暗色由 CSS 表达（`[data-theme="dark"]`），JS 不持有任何色值。

## 二、令牌类事实

### I-5 绕过令牌的颜色在暗色模式下**必然**失效

```css
.card { background: #FFFFFF }   /* 暗色模式下还是白底 */
```

不是"可能不好看"，是**令牌切换对它没有任何作用**——它根本没引用令牌。

- 门禁：`hardcode-gate.py`
- 例外判据（写死在门禁里）：**判断"这是内容色还是效果色"**。
  阴影是光影效果，不是主题内容 ⇒ 允许裸值。内容底色 ⇒ 必须令牌。
  已发生的事故：把 `switch.css` 的阴影也改成令牌，反而是错的。

### I-6 `tokens.css` 是全库配色/间距/字号的**唯一汇聚点**

改它的影响面 = 全库。这是依赖拓扑的结果。

- 门禁：`impact-report.py` —— 它把"改了什么 ⇒ 必须重跑什么"机械化，
  **不靠人判断**。

### I-7 令牌有第二份真值来源 ⇒ 必然漂移

两份手写的值**都能各自自洽**，所以**测不出来**，只会慢慢错开。

- 实证：`theme-toggle.js` 第一版手写的 20 个暗色令牌，17 个与 tokens.css 不一致，
  连名字都编错（`--warn` / `--danger-soft`，真名 `--warning` / `--danger-bg`）。
- 缓解：真值只有一份，其余**全部生成**（`theme-sync.py`）+ `--check` 门禁。
- 已根治的实例：暗色不再由 JS 持有值——CSS 自己表达，JS 只翻属性。

## 三、状态表达类事实

### I-8 状态写在 DOM 属性上是**可读的事实**；写在 class 上是**不可见的副作用**

| 写法 | 谁能读到 | 改坏了 JS 之后 |
|---|---|---|
| `data-state="closed"` | 任何人、任何工具、任何时刻 | 值还在那儿，可被断言、可被门禁检查 |
| 状态类名（由 JS add/remove） | 只有"JS 正确执行过"才能读到 | class 消失，CSS 规则还在 ⇒ **静默错乱，无报错** |

**这是 PPT 事故的技术根因**：状态不在 DOM 里 ⇒ 无法从文档反推当前状态 ⇒
每次局部修改都是在看不见状态的情况下盲改 ⇒ 改 A 坏 B。

**实证（比"理论上有风险"更硬）**：本库曾长期两套并存——CSS 同时写
`.tooltip` 的状态类与 `[data-state="open"]`，但 JS 只加前者。后果有两层：

1. 文档告诉使用者"请改用 `data-state`"，而**这个分支从来不会被设上** ⇒
   承诺了一个不工作的 API；
2. 一次半自动改写把 `.a.is-disabled .b` 拆成 `.a.is-disabled, .a[data-state] .b`
   ⇒ 前半截**丢了后代选择器**，规则落到容器自己身上，真正该变灰的 `.b`
   再也没有这条样式。**这个 bug 已随发布版本出去了**，且不报错、页面照常显示。

- 已整改：`is-*` 归零，状态一律走属性（详见 `API.md` 的迁移表）。
- 教训：**两套表达不是"冗余"，是"其中一套必然是死的，而且没人看得出来"。**

### I-9 状态应当是**枚举字符串**，不是布尔

`data-state="open" | "closed"` 可以表达第三态（`closing`——动画中）。
`isOpen: boolean` 不能。

⇒ 这不是风格偏好，是**表达能力的客观差异**。

## 四、验证类事实

### I-10 一个"报告通过但什么都没检查"的门禁，比没有门禁更危险

没有门禁 ⇒ 你知道要自己看。
假绿门禁 ⇒ 你以为有人在看。

- 实证 1：`es5-gate.py` 传 `--dir` 时扫 **0 个文件**，却报 PASS。
  它源码第 98–103 行自己就写了这个警告，但调用方一直传 `--dir`。
- 实证 2：`shot-baseline.py` 一张图都没截到，报 `OK 23 / 0 个页面观感一致`。
- 实证 3：`api-snapshot.py` 注入 `Select.destroy()` 幻觉 API，仍报 OK。
- 实证 4：16 个门禁用 `--dir .`，扫进了 `node_modules`。
- 实证 5：**代码说自己会检查，但没有任何门禁跑它**。
  `adapters/presentation/check.js` 声称守五条呈现判据（版面登记 / 单页上限 /
  必须有标题 / 层级不跳级 / 禁页面级选择器），而 `core-boundary` 只验了
  `to-doc.js` 的往返 ⇒ `check.js` **一次都没被执行过**。
  读 README 的人会以为有人在看，实际上没人看 —— 这就是假绿的一种，
  而且是最难发现的一种：**它不产出任何报告**。
  ⇒ 修法：`presentation` 门禁对合规 / 违规两份 fixture 实跑，
  要求五条判据**各命中一次**，并带反向控制（弄瘫判据 ⇒ 门禁必须认出它失效）。
- 实证 6：**门禁在测另一棵树**。视觉回归用固定端口起静态服务，
  端口被占时子进程**立刻静默退出**，而 `Popen` 不报错、返回值正常
  ⇒ 截图全部打到了另一个目录的残留服务上。
  之所以被发现，是**修好了 CSS 之后 diff 数字一字未变**。
  ⇒ 修法：改用操作系统分配端口（bind 0）+ canary 校验（拉文件与磁盘字节比对）。

⇒ **因此本库每一道新门禁都必须做反向控制**：注入反例，证明它会红。
**没有反向控制的门禁不算门禁。**
⇒ 另外：**门禁依赖的每一份输入都要能被证明是"本次的"** ——
   端口、临时目录、缓存文件，任何一个指向别处，报告再漂亮也是假的。

### I-11 解析 CSS/HTML 时，正则不是解析器

- 实证：`prefix-build.py` 第一版把 `this.tablist` 当成选择器 `.tablist` 改写 ⇒ `SyntaxError`。
- 缓解：改写后对所有 JS 跑 `node --check`；选择器规则加 `(?<![\w$])` 前缀约束。

### I-12 浏览器不认识的声明、悬空的 `var()` 引用 ⇒ **静默失效**

写错属性名**不报错、不告警、不影响后续解析**：整条声明被丢弃，其余照常生效。
`var(--x)` 里的 `--x` 从未定义且没有兜底 ⇒ 该声明在**计算值阶段**无效，整条丢弃。

- 实证：全库 19 处写了 `border-inset-inline-start` / `-end` ——
  这不是一个存在的 CSS 属性（正确的是 `border-inline-start` / `-end`）。
  机械验证：`CSS.supports()` 两种形式与 `element.style.setProperty()` 三处一致
  返回 `false`。⇒ 这些边框**从来没有被渲染过**；而配套的
  `border-left-color` 只是给一条 0 宽、style 为 none 的边上色 ⇒ 全线不可见。
- 为什么别的门禁抓不到：它不影响解析、不抛异常、不改变任何可断言的行为，
  只是**观感**缺了一块；而观感只有视觉回归能验。
- 门禁：`css-validity`（判据交给浏览器自己，不手写属性白名单 ——
  手写的那份是第二份真相源，见 I-7）。

### I-13 `npm install file:` 不做打包，会连未发布目录一起软链进来

- 实证：一度以为 `npm pack` 泄漏内部文档。实测证伪——真实 `npm pack` + 安装是干净的。
- 教训：**用真实 tarball 安装验证，不要用 `file:` 的假象下结论。**
- 门禁：`pack-smoke.sh`。

### I-14 同一语义的样式若在每个使用点各写一份，"改一处"在物理上不成立

- 实证：一次成套多页制作中，想改一处"全局"的东西，整批页面立刻崩。
  机械测量（39 个使用点）：页面框、内容列、标题阶梯、行内代码、说明块
  这几样"全局"的东西，各自出现在 21–36 个使用点、同一个选择器有 7–16 种写法，
  其中若干**已经存在共享定义**，使用点仍在重抄。
- 反方向的机械证据：把改动之前的版本取出，用同一把尺子量
  "改一个全局变量，这个使用点跟不跟着变" ⇒ 36 处不跟随。
- 推论：**"全局可改"不是写法问题，而是"存在唯一汇聚点"这一事实的结果。**
  没有汇聚点，改动的完整性就只能靠逐点同步，而逐点同步必然漏。
- 推论二：一个已被收编的选择器若在使用点仍被书写，会被更高特异性的定义
  **静默盖掉**，成为死声明 —— 不报错、不影响解析，只在"改了却没变"时才暴露。
- 门禁：`shell`（禁止使用点重抄骨架）+ `skel-lever`（在真实浏览器里要求
  每一个使用点都跟随同一全局变量的改动，并含"不引骨架的使用点不得被影响"的反向控制）。

## 五、这一层**不**包含什么

明确排除，避免这一层被污染后失去"永不变"的性质：

| 不写在这里 | 应该去哪 | 理由 |
|---|---|---|
| "改之前先跑 impact-report.py" | `GUIDANCE.md` | 这是工作建议。更强的模型自己就能判断影响面 |
| "AI 应该先读 README" | `GUIDANCE.md` | 同上 |
| "本版有 26 个组件" | `ai/components.json`（Contract） | 会随版本变 |
| "某档位只允许某成熟度的组件" | `ai/profiles.json`（Contract） | 这是**约定**，不是事实，可以改 |
| "不要写 magic number" | `GUIDANCE.md` | 这是品味建议，不是物理事实 |

## 六、怎么保证这一层不被污染

`05-audit/invariant-gate.py` 会检查：

1. 本文件中**不出现**任何组件名、令牌名、版本号、档位名（出现 ⇒ 那是 Contract 的内容）
2. 本文件中**不出现** "应该 / 建议 / 推荐 / 最好" 这类措辞（出现 ⇒ 那是 Guidance 的内容）
3. `ai/contract.schema.json` 里声明的 `invariants` 条目，与本文件的锚点**一一对应**

⇒ 门禁先于人情。想往这层塞东西，得先说服门禁。
