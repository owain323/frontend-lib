# 无障碍一致性声明

**目标等级：WCAG 2.2 Level AA。** 本文按 **成功准则（Success Criterion）逐条**说明
状态、证据来源与缺口 —— 不是"我们很重视无障碍"，而是"哪一条过、哪一条没过、凭什么"。

| 项目 | 值 |
|---|---|
| 声明适用版本 | agentcss `0.13.2` |
| 声明日期 | 2026-10-29 |
| 复核节奏 | 每次发版前重跑（`npm run gate` 内含全部证据） |
| 范围 | 本库交付的 CSS / JS、全部 `demo.html`（组件页 + 图表页 + 组合页）、以及文档站生成的页面 |
| 不在范围 | 使用者拿这些组件拼出来的业务页面（那是你的无障碍责任，不是库的） |

判读方式只有一句：**表里写「通过」的，下面都给出了可复现的命令；写「部分」或「未验」的，
就是没做到，不要按"应该没问题"理解。**

## 二 · 证据是怎么来的（以及它盖不住什么）

### 自动化（可复跑，命令都在 `05-audit/`）

| 手段 | 覆盖 | 最近结果 |
|---|---|---|
| `axe-core`（`a11y-scan.js`） | 39 页（37 组件 demo + 2 个非组件页） | **0 类违规**，991 条规则通过 |
| 反向控制（注入 5 类典型违规） | 证明上一条不是"没查" | 5 类全部抓到 |
| `heading-outline.js`（人工工具） | **全部 HTML：96 页 / 887 个标题** | 0 处跳级 · 每页恰好 1 个 `h1` · DOM 标题数 == 无障碍树 heading 数 |
| `a11y-ax.js` 可访问性树 | **全部 `demo.html`（现 40 个）**；清单与磁盘不一致即红 | 0 个无名控件；40 份朗读序列快照在 `10-review/a11y-tree/` |
| `contrast.py` / `dark-contrast.js` | 亮 / 暗两套，逐对实算 | 正文 ≥ 4.5:1 |
| `zoom-reflow.js` | 40 页 × 3 条 AA 硬项 | 320px 不横滚 · 200% 不裁字 · 焦点不被遮挡 |
| `focus-ring-check` / `focus-return-check` / `keyboard-nav` | 焦点可见、焦点归还、键盘路径 | 全绿 |

### 人工（**已执行一轮，仍缺人耳与第二平台**）

自动化的天花板必须说清楚：**axe 只能覆盖约 30–40% 的 WCAG 问题**，而且它听不见。

2026-10-30 用 NVDA 2026.3 + Edge（Windows 10 22H2）跑了两轮：把 NVDA 的朗读日志写到
文件，逐条取它交给语音合成器的原文。九页结果见
[无障碍人工测试协议](A11Y-MANUAL-PROTOCOL.md) 第三节。

第一轮覆盖 Tab 遍历、禁用态、错误说明与浮层焦点；第二轮补的是**标题层级**——
用读屏的「下一个标题」跳（`H`），逐页核对它念出的级别与页面结构是否一致。
同一轮里把机器侧的结构扫描从 9 页扩到全站 96 页（887 个标题）。

**它证明的是"NVDA 念了什么"，不等于"人听着顺不顺"。** 仍然缺：

1. **人耳旁听** —— 证据是日志文本；语气、打断、重复播报这类问题不在其中。
2. **macOS VoiceOver / Android TalkBack** —— 一条记录都没有。
3. **9 处「待人工」结论**（例如图表的替代文本是否真的描述了数据）。

这一轮还确认并修掉了一条真缺陷：`table` 的列头按钮会把排序符号 `↕` 念出来
（来源是 `table.css` 的 `::after` 伪元素文本，Chromium 把它算进了可访问名）。
自动检查抓不到它 —— 可访问名"非空"就算过。
修法是把字形换成 `mask` 图像（`content` 留空），视觉与三态形状不变；
改完用 NVDA 复听，表头只剩「公司 · 按钮」。详见协议页第三节。

## 三 · 已知缺口（按影响排序）

1. **没有人耳旁听与第二平台记录**：2026-10-30 有一轮 NVDA 脚本实录（见协议页），
   但 VoiceOver / TalkBack 仍为空白，语气与播报时机也没人判断过。
   这是与 Carbon / Spectrum 那类一致性报告差距最大的一处。
2. **没有 VPAT / ACR 正式报告**。采购流程要的那种文档本库没有出；
   上面那张 SC 表可以当它的替代品，但它不是法律意义上的 ACR。
3. **强制色板（forced-colors）只覆盖 6 个 CSS**，Windows 高对比度模式未逐组件验证。
4. **RTL 已进渲染判据与视觉基线，但没进真机**：
   `rtl-render.js` 判 37 页（RTL 不横滚 / 阿·希文字膨胀 1.3× 不破相 /
   方向性字形镜像），`shot-baseline.py --dir rtl` 有 13 张视觉基线
   （覆盖"镜像错了但不溢出不改字形"那一类）。
   **仍然缺的是**：母语 RTL 使用者的实际阅读体验、iOS/Android 真机 RTL 截图，
   以及「页面加载后再切 `dir`」时组件内部状态是否需要重算。
   最后这条的现状是：CSS 会立刻响应（树形箭头、栅格、滑入方向都靠 CSS），
   但凡是 JS 在挂载时把方向读进变量的地方都不会重算 —— 本库目前没有这种写法，
   这一点靠 `rtl-render` 的"挂载后再改 dir"路径间接守着。
5. **1.4.12 文本间距**未按极端注入验证；**1.4.13** 未验证"提示内文字可选中"。
6. **Android 系统 WebView 未验证**，真机矩阵里它是 ❌（见[浏览器支持矩阵](../SUPPORT.md)）。
7. **`prefers-contrast: more` 未单独验收**（只做了 `forced-colors`）。

## 四 · 自己验一遍

```bash
# 一条命令跑完全部无障碍相关判据（含反向控制）
npm run gate:fast                       # 静态层：结构 / 契约 / 文档事实
node 05-audit/a11y-scan.js              # axe（需要本地静态服务 :8000）
node 05-audit/heading-outline.js        # 全站标题大纲：96 页 / 887 个标题（同一服务）
node 05-audit/a11y-ax.js                # 可访问性树 + 名称判据
node 05-audit/zoom-reflow.js            # 200% / 320px / 焦点遮挡
node 05-audit/rtl-render.js             # RTL 渲染 + 阿/希膨胀 + 字形镜像
node 05-audit/a11y-ax.js --selftest     # 证明上面那条判据抓得到问题
node 05-audit/zoom-reflow.js --selftest # 同上
node 05-audit/rtl-render.js --selftest  # 同上
python 05-audit/shot-baseline.py --check --dir rtl   # RTL 视觉基线
```

`python3 05-audit/a11y.py --dir .` 会连 `node_modules` 一起扫，
那里面的第三方 HTML 会报一堆与你无关的问题 —— 门禁里用的是逐目录调用，别用 `--dir .`。

## 五 · 报告问题

无障碍问题按**缺陷**处理，不按"改进建议"处理。开 issue 写清三件事：
**控件 + 输入方式（键盘 / 读屏 / 触摸）+ 期望行为**。

如果你能提供自己机器上的读屏结果（读到了什么、和预期差在哪），
它的价值高于本页任何一条自动化结论 —— 那正是第 2 节里空着的那一块。
