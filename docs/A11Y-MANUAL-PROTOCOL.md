# 无障碍人工测试协议（读屏）

**为什么需要这份东西**：自动检查（axe / 可访问性树）能证明"每个控件有名字、顺序稳定"，
但证明不了"念出来是否**合理**"。这一页把这件事变成**可执行、可复现、可填表**的动作，
时长约 20 分钟。

**当前状态：已执行两轮（2026-10-30）。** 九个页面都跑过 Tab 遍历，浮层焦点在
`overlay` / `drawer` 上验到；**标题层级（`H` 键逐级跳）在第二轮补齐**——九个页面
共 107 个标题，逐条与页面结构对得上。第一轮修掉的缺陷、第二轮的破坏实验，
以及三趟才拿到干净数据的那三个操作坑，都写在第三节。

证据形态要说清楚：**不是人耳旁听**，是让 NVDA 把朗读日志写到文件，逐条取它交给语音
合成器的原始文本（`IO - speech.speech.speak`）。这比人耳更可复现、可存档，但它证明的
是"NVDA 念了什么"，不覆盖"听起来是否别扭"。

## 二 · 每页只做这 5 件事（NVDA 键位在括号里）

1. **按 Tab 走一遍**（走的是焦点顺序，与浏览光标停在哪无关），听到的每个控件都要有
   **说得通的名字**。听到 "button"、"未标记"、"undefined"、只有图标名 ⇒ ❌ 记下来。
2. **用读屏的"下一个标题"跳（NVDA `H`）**，标题层级应当是 1 → 2 → 3，不跳级。

   > **三个实操坑**（2026-10-30 实测，三个都踩过，踩完才拿到干净结果）：
   > - **换一个查询串再打开**。NVDA 按文档 URL 记忆浏览光标：同一个 URL 再开一次会恢复
   >   上次的位置，若上次停在文末，按 `H` 只会念「往下没有标题」——看起来像"本页没有标题"。
   > - **`h1` 用 `H` 再 `SHIFT+H` 取**。加载后的光标落点不固定：有时正好在 `h1` 上
   >   （按 `↑` 直接念出「标题 1 级 + 页面名」），有时落在紧随其后的导语段落上。
   >   稳妥的做法是先按一次 `H` 走到第一个 `h2`，再按 `SHIFT+H` 退回来 —— 那一条必然是 `h1`。
   > - **末端那句「往下没有标题」是证据，不是失败**。它证明 `H` 已经走过本页最后一个标题。
3. **把焦点放到一个禁用控件上**，它应当被念成"不可用"（而不是干脆跳过或念成正常按钮）。
4. **触发表单错误**（页面里带校验的那块），错误文字应当被**紧跟控件**念出，
   不是只在屏幕右上角飘一条。
5. **打开一个浮层（对话框 / 抽屉）**：焦点应进入浮层内部，`Esc` 关闭后
   焦点应回到**打开它的那个按钮**。

> 判读标准只有一条：**不看屏幕，只听**。听到的内容能不能让你知道该做什么。
> 一旦你需要看屏幕才能确定发生了什么，那一处就是缺陷。

> **为什么后三行是补的**：`accordion` / `drawer` / `dropdown` 这三个都是 beta 组件
> （`ai/components.json` 当前记 4 个 beta），而它们升 stable 的判据之一就是「行为零欠账」
> ——人工读屏是这件事**唯一的用户侧证据**。
> 只覆盖 `overlay` 一个浮层，等于对其他浮层的真实表现没有任何记录。

**本轮跑出来并已修掉的一条真缺陷**：`table` 的列头按钮被念成「公司 · `↕` · 按钮」——
那个 `↕` 来自 `table.css` 里 `.table__sort::after` 的 `content`，Chromium 把伪元素文本算进了
可访问名。**自动检查抓不到它**（可访问名"非空"就算过），212 道门禁里也没有一道看这个。

改法：把字形换成 `mask` 图像（`content` 留空），三态形状仍是 `↕ / ↑ / ↓`，
颜色靠 `currentColor` 跟着主题走，标记结构一个字符都不用动。

**为什么不用 `content: "↕" / ""` 那个一行改法**（2026-10-30 实测更正）：
早先这里写着"Firefox 不支持替代文本语法"——**那是错的**。三个引擎实测下来都被接受，
而且都能把 `↕` 从可访问名里去掉：

| 写法 | Chromium | Firefox | WebKit |
|---|---|---|---|
| `content: "↕" / ""` | 显示 · 名=`公司` | 显示 · 名=`公司` | 显示 · 名=`公司` |
| `content: "↕" / "排序"` | 显示 · 名=`公司 排序` | 显示 · 名=`公司排序` | 显示 · 名=`公司排序` |
| `mask`（本库） | 显示 · 名=`公司` | 显示 · 名=`公司` | 显示 · 名=`公司` |
| `content: "↕"`（原写法） | 显示 · 名=`公司↕` | 显示 · 名=`公司↕` | 显示 · 名=`公司↕` |

真正拦住它的是**老引擎**：这套语法要 Chromium 108 / Firefox 128 / Safari 17.4 起才认，
而不认的引擎会**把整条声明丢掉** ⇒ 箭头彻底消失（比念出符号更糟）。
支持矩阵里有 Android 百度浏览器（Chromium 97，见 [LAYER-BASELINE](LAYER-BASELINE.md)），
落在门槛之外。🔴 **这一条是按版本门槛推断的，没有在 Chromium 97 上实测过** ——
说的就是"没测的不算已验证"。

改完用 NVDA 复听：表头只剩「公司 · 按钮」；`table-check` 的排序判据也跟着改成
读 `mask` 的自定义属性（破坏实验验证过：把降序箭头改成升序形状，判据当场红）。

**`dropdown` 那行要连着对照读**：同样的操作在极简 APG 对照页上表现一致（↓ 被吃），
所以"方向键读不出菜单项"不是本库特有。但另一件事是**真缺陷**：用 NVDA 在浏览模式下
按 Enter，它会把这次按键变成一次点击 ⇒ 走的是 click 分支，而本库原来只在键盘分支里
聚焦首项 ⇒ 菜单打开了、焦点还在按钮上，菜单项永远进不去。
自动门禁当时是绿的，因为它只测了 `↓` 这条键盘路径。
**修法与判据**：把聚焦首项收进 `open()`（两条路径共用），并补一条"点击打开也聚焦首项"。

### ② 那一格是怎么填的：两条通道，各测一半

标题层级容易被当成"看一眼 DOM 就知道"的事，但**"结构对不对"和"读屏跳得对不对"
是两件事**。所以这一格用两条互不依赖的通道各测一遍：

| 通道 | 覆盖 | 这一轮的结果 |
|---|---|---|
| 机器 · 运行时 DOM + 可访问性树 | **96 个页面、887 个标题**（`node_modules` / `dist` 之外的全部 HTML，空夹具除外） | 每页恰好一个 `h1`；跳级 0 处、空名 0 个；层级分布 `h1×96 · h2×581 · h3×210`（没有 h4–h6）；DOM 里的标题数与无障碍树里的 heading 节点数**逐页相等** |
| 读屏 · NVDA `H` 键实录 | 协议表里的 **9 页、107 个标题** | **107/107 条**念出的级别与页面结构逐条一致；九页走到底时都念「往下没有标题」 |

机器侧不是"跑绿了就算"。这三条 axe 规则（`heading-order` /
`page-has-heading-one` / `empty-heading`）都做过破坏实验：

| 注入的破坏 | `heading-order` | `page-has-heading-one` | `empty-heading` |
|---|---|---|---|
| 基线（不动） | 绿 | 绿 | 绿 |
| `h2` 后插 `h4`（跳级） | **红** | 绿 | 绿 |
| 删掉唯一的 `h1` | 绿 | **红** | 绿 |
| 清空一个 `h3` 的文本 | 绿 | 绿 | **红** |
| 反向对照：`h3` 后插 `h4`（合法） | 绿 | 绿 | 绿 |

最后一行是关键：合法层级仍然全绿，说明它不是"见到 `h4` 就报"。

> **机器侧可复跑**：`node 05-audit/heading-outline.js`（先起本地静态服务），
> 末行会打印 `96 页 · 887 个标题（h1×96 · h2×581 · h3×210）· 0 页异常`。
> 它不是门禁，是取证工具：结构本身已由 axe 那三条规则守着，它负责的是
> "把整站每个标题都数一遍"这件事，以及第四条判据（DOM 标题数 == 无障碍树 heading 数）。
>
> **读屏侧不进仓库**：实录脚本依赖一台装了 NVDA 的 Windows 机。复核方式是按第二节
> 第 2 条自己走一遍——九页的层级序列在上表每行的备注里都抄了，对不上就是有问题。

状态只填三种：**通过** / **失败（附听到的内容）** / **未执行**。
"大概没问题"不属于这三种，不要写。

## 五 · 为什么这份协议要写进仓库

因为"我们打算做读屏测试"和"我们做过读屏测试"在仓库里长得一模一样 ——
除非有一张**带状态列的表**。第一轮填这张表时，九页里有六页的"标题层级"写着"未执行"；
那一列记录的不是进度，而是**边界**。第二轮把那一列填满，边界就移动了一格 ——
现在还剩 macOS VoiceOver 与 Android TalkBack 两格空白（见第四节第 2 条）。
