# 无障碍人工测试协议（读屏）

**为什么需要这份东西**：自动检查（axe / 可访问性树）能证明"每个控件有名字、顺序稳定"，
但证明不了"念出来是否**合理**"。这一页把这件事变成**可执行、可复现、可填表**的动作，
时长约 20 分钟。

**当前状态：未执行。** 下面那张结果表是空的 —— 这不是省略，是事实。
跑完并填上之后，[无障碍一致性声明](ACCESSIBILITY.md) 里"没有真机读屏记录"那一条才能划掉。

## 一 · 准备

| 路径 | 系统 | 读屏 | 浏览器 |
|---|---|---|---|
| A | Windows 10/11 | [NVDA](https://www.nvaccess.org/download/)（免费） | Chrome 或 Edge |
| B | macOS | VoiceOver（系统自带，`Cmd + F5`） | Safari |

被测页面（本地起一个静态服务，仓库根目录执行）：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
# 然后访问 http://127.0.0.1:8000/02-primitives/button/demo.html
```

要测的 6 个页面（一个组件一类交互语义，覆盖主要风险）：

| # | 页面 | 它想证明什么 |
|---|---|---|
| 1 | `02-primitives/button/demo.html` | 按钮的名字念得出、禁用与加载态念得对 |
| 2 | `02-primitives/input/demo.html` | 标签与错误说明能被一起念出来 |
| 3 | `02-primitives/choice/demo.html` | 单选 / 复选的分组关系念得对 |
| 4 | `03-patterns/tabs/demo.html` | 标签页的选中态与面板归属念得对 |
| 5 | `03-patterns/overlay/demo.html` | 对话框打开时焦点进入、关闭后归还 |
| 6 | `04-recipes/table/demo.html` | 表头与单元格的关联念得出来 |

## 二 · 每页只做这 5 件事（NVDA 键位在括号里）

1. **从页面顶部按 Tab 走一遍**，听到的每个控件都要有**说得通的名字**。
   听到 "button"、"未标记"、"undefined"、只有图标名 ⇒ ❌ 记下来。
2. **用读屏的"下一个标题"跳（NVDA `H`）**，标题层级应当是 1 → 2 → 3，不跳级。
3. **把焦点放到一个禁用控件上**，它应当被念成"不可用"（而不是干脆跳过或念成正常按钮）。
4. **触发表单错误**（页面里带校验的那块），错误文字应当被**紧跟控件**念出，
   不是只在屏幕右上角飘一条。
5. **打开一个浮层（对话框 / 抽屉）**：焦点应进入浮层内部，`Esc` 关闭后
   焦点应回到**打开它的那个按钮**。

> 判读标准只有一条：**不看屏幕，只听**。听到的内容能不能让你知道该做什么。
> 一旦你需要看屏幕才能确定发生了什么，那一处就是缺陷。
