# 无障碍人工测试协议（读屏）

**为什么需要这份东西**：自动检查（axe / 可访问性树）能证明"每个控件有名字、顺序稳定"，
但证明不了"念出来是否**合理**"。这一页把这件事变成**可执行、可复现、可填表**的动作，
时长约 20 分钟。

**当前状态：已执行一轮（2026-10-30）。** 九个页面都跑过 Tab 遍历，浮层焦点在
`overlay` / `drawer` 上验到，**标题层级（`H` 键逐级跳）本轮没做**，结果表里如实写着
"未执行"。

证据形态要说清楚：**不是人耳旁听**，是让 NVDA 把朗读日志写到文件，逐条取它交给语音
合成器的原始文本（`IO - speech.speech.speak`）。这比人耳更可复现、可存档，但它证明的
是"NVDA 念了什么"，不覆盖"听起来是否别扭"。

## 一 · 准备

| 路径 | 系统 | 读屏 | 浏览器 |
|---|---|---|---|
| A | Windows 10/11 | [NVDA](https://www.nvaccess.org/download/)（免费） | Chrome 或 Edge |
| B | macOS | VoiceOver（系统自带，`Cmd + F5`） | Safari |

被测页面（本地起一个静态服务，仓库根目录执行）：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
# 然后访问 http://127.0.0.1:8000/02-primitives/button/demo.html
```

要测的 6 个页面（一个组件一类交互语义，覆盖主要风险）：

| # | 页面 | 它想证明什么 |
|---|---|---|
| 1 | `02-primitives/button/demo.html` | 按钮的名字念得出、禁用与加载态念得对 |
| 2 | `02-primitives/input/demo.html` | 标签与错误说明能被一起念出来 |
| 3 | `02-primitives/choice/demo.html` | 单选 / 复选的分组关系念得对 |
| 4 | `03-patterns/tabs/demo.html` | 标签页的选中态与面板归属念得对 |
| 5 | `03-patterns/overlay/demo.html` | 对话框打开时焦点进入、关闭后归还 |
| 6 | `04-recipes/table/demo.html` | 表头与单元格的关联念得出来 |

## 二 · 每页只做这 5 件事（NVDA 键位在括号里）

1. **从页面顶部按 Tab 走一遍**，听到的每个控件都要有**说得通的名字**。
   听到 "button"、"未标记"、"undefined"、只有图标名 ⇒ ❌ 记下来。
2. **用读屏的"下一个标题"跳（NVDA `H`）**，标题层级应当是 1 → 2 → 3，不跳级。
3. **把焦点放到一个禁用控件上**，它应当被念成"不可用"（而不是干脆跳过或念成正常按钮）。
4. **触发表单错误**（页面里带校验的那块），错误文字应当被**紧跟控件**念出，
   不是只在屏幕右上角飘一条。
5. **打开一个浮层（对话框 / 抽屉）**：焦点应进入浮层内部，`Esc` 关闭后
   焦点应回到**打开它的那个按钮**。

> 判读标准只有一条：**不看屏幕，只听**。听到的内容能不能让你知道该做什么。
> 一旦你需要看屏幕才能确定发生了什么，那一处就是缺陷。

> **为什么后三行是补的**：`accordion` / `drawer` / `dropdown` 这三个都是 beta 组件
> （`ai/components.json` 当前记 4 个 beta），而它们升 stable 的判据之一就是「行为零欠账」
> ——人工读屏是这件事**唯一的用户侧证据**。
> 只覆盖 `overlay` 一个浮层，等于对其他浮层的真实表现没有任何记录。

**本轮跑出来的一条真缺陷**：`table` 的列头按钮被念成「公司 · `↕` · 按钮」——那个
`↕` 来自 `table.css` 里 `.table__sort::after` 的 `content`，Chromium 把伪元素文本算进了
可访问名。**自动检查抓不到它**（可访问名"非空"就算过），212 道门禁里也没有一道看这个。

单行改法是 `content: "↕" / ""`（CSS 替代文本），但 Firefox 不支持该语法、会让箭头直接
消失；要改就得换成 `aria-hidden` 的 SVG。**这是设计决策，本页只记录现象，不代替决策。**

**`dropdown` 那行要连着对照读**：同样的操作在极简 APG 对照页上表现一致（↓ 被吃），
所以"方向键读不出菜单项"不是本库特有。但另一件事尚未定论：真实 Edge 下 UIA 读到
打开后焦点**仍在按钮**（`ExpandCollapseState=Expanded` 而 `FocusedElement=Button`），
而 `dropdown-check` 的「↓ 打开菜单并聚焦首项」在 headless 下是绿的。
**这两者不一致，需要定位后才知道该改代码还是改门禁** —— 在定位前不要据此改库。

状态只填三种：**通过** / **失败（附听到的内容）** / **未执行**。
"大概没问题"不属于这三种，不要写。

## 五 · 为什么这份协议要写进仓库

因为"我们打算做读屏测试"和"我们做过读屏测试"在仓库里长得一模一样 ——
除非有一张**带状态列的表**。这张表现在全部写着"未执行"，
它记录的不是进度，而是**边界**：本库目前能承诺的东西到哪为止。
