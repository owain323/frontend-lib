sparkline · 迷你趋势图

迷你趋势图：无坐标轴、纯形状，适合表格内嵌的一行走势

  • 09-assets/sparkline/demo.html
  • 09-assets/sparkline/sparkline.css
  • 09-assets/sparkline/sparkline.js

在一行里显示"最近走势"。它是辅助，不是图表。

用法#

<span class="sparkline" data-spark="12,18,15,24,22,31,28"></span>
属性值默认
data-spark逗号分隔的数字—
data-spark-typeline / bar / arealine
data-spark-height像素32
data-spark-colorCSS 颜色或 var(--x)var(--accent)
data-spark-fillno 关闭面积填充填
data-spark-lastyes 标出最后一个点不标
data-spark-animateno 关闭入场动画开

更新数据：

el.setAttribute('data-spark', '1,2,3');
Chart.emit(el);          // 重画这一个
Chart.update(container); // 重画某区域内全部

🔴 无障碍：它没有可读的文本等价物#

纯 SVG 路径对读屏没有意义 —— 读屏只会说"图像"。

⇒ 本组件刻意不加 role="img"（那会让人以为它有可读的替代文本，而它没有） ⇒ SVG 标了 aria-hidden="true" + focusable="false" ⇒ 要给出可读的值：在旁边放数字，或用「名字 + 当前值 + 涨跌」的组合 ⇒ 必须配文字的场景：数值重要时（如"营收 128 万，同比 +3.2%"）。纯装饰的小图可以不配。

只放 sparkline 不放数字 = 把视觉当成唯一通道，这是反例。

动画#

用 stroke-dasharray 做"从左往右画出来"的效果。

为什么不用 JS 逐帧： ① 零 JS 帧循环，动画交给合成器 ② 可被 prefers-reduced-motion 一行 CSS 关掉 ③ 几十个同时动画也不掉帧

关掉动画的三种情况（CSS 里都做了）： ① 用户在系统里说了"减少动态效果"（WCAG 2.3.3，前庭功能障碍者会眩晕） ② 打印时（@media print） ③ 元素上写 data-spark-animate="no"

为什么自己写而不引库#

调研了 GitHub 上几个零依赖方案，最小的 mitjafelicijan/sparklines 是 6390 字节 / 195 行 / gzip 1675 字节、BSD-2 许可（可商用）—— 它做得很好，值得参考。

但没有直接引，两个原因（都不是嫌它差）：

它本库要求
语法const + 箭头函数（ES6）ES5（精简档 跑在 某项目 的 WebView，版本不确定）
颜色data 属性传 HEX / 颜色名令牌驱动（换主题要跟着变）

⇒ 借鉴它的接口设计（data 属性驱动、零依赖、BSD 思路），实现按本库约束重写。

当前体量：sparkline.js 约 8 KB · sparkline.css 约 2 KB · 零依赖。

🔴 修两个把线画坏的 bug（真机实测截图指出）#

① preserveAspectRatio="none" ⇒ 横向拉伸#

它允许 x/y 独立缩放。本组件 viewBox 宽度已经是容器实际像素宽， width:100% 渲染到同一宽度 ⇒ 横向本来就不该缩放，但 none 仍会在容器宽 ≠ viewBox 宽时（整数舍入 / 滚动条 / flex 未稳定）把图形拉变形。

⇒ 删掉，走默认 xMidYMid meet：1px 就是 1px，比例有出入也只等比留边。

② 🔴 CSS 的 fill 覆盖了 fill="none" 属性#

我原来写「path / rect / circle 一律 fill: var(--spark-c)」—— CSS 优先级高于 SVG presentation attribute， JS 里写的 fill="none" 被完全无视。

实测：fill 属性 = none，计算值 = rgb(27,77,143) ⇒ 折线被填成实心多边形 ⇒ 看起来是「扁平的色带」而不是趋势线。

这才是"色带"的直接原因（① 只是让它更扁）。

⇒ 修法：按类型分四类，不靠属性覆盖（属性打不过 CSS）： .spark-line 描边 / .spark-area 填充 / .spark-bar 填充 / .spark-dot 填充。

③ 连带发现：动画类被牵连（真 bug）#

重写外观后 spark-line 必须常驻（它负责 fill:none），于是旧逻辑「没动画就不加 spark-line 类」形同虚设 —— 动画会无视设置照播。

⇒ 拆出独立的 .spark-anim 专管动画。契约测试已改判据并锁住。

🔴 MISSING != ZERO（最重要的一条）#

空值和 0 是两件事。

写法含义画成什么
data-spark="1,0,3"1、真的 0、3一条连续的线，中间有个低谷
data-spark="1,,3"1、没数据、3两段线，中间断开
data-spark="1,2,3,4,"末点没数据两段线，不画末点圆点

为什么这么重要：一条横跨缺失点的线，等于在说"从 1 平滑升到 3，中间一切正常" —— 而真相是"中间没数据"。 数据缺失被画成了平稳过渡，这是图表最容易忽略、最会误导人的一种错。

契约来源（不是我想的）：ChartsPage.tsx 第 10 行自己写着

「MISSING != ZERO / INVALID != MISSING / 过滤必须可见」

它自己做到了 connectNulls={false} 且 0 处遗漏 —— 本库照它做，并在自己的契约测试里锁死这六条。

实现要点：

  • parsePoints 把空值 / - / null / NaN 都保留成 null（不是 0）
  • scale 求最值时排除 null（否则 Math.min(1, null, 3) === 1 会把图压扁）
  • draw 把序列切成连续段，每段画一条 path，段间留空
  • 柱状图：缺失点不画柱（画成 0 高度等于假装"这里是 0"）

边界情况（都实测过）#

输入行为
少于 2 个有效点不画（画不出趋势）
全部缺失（,,,,）不画，且不崩（scale 返回 null 有防护）
中间缺失断开成两段，不连线
全部相同（10,10,10）人工造上下界，不除零，画成一条水平线
单点成段画成一个小圆点（否则那段"什么都不画"，用户以为图坏了）
元素宽度为 0（隐藏中）用 data-spark-width 或等布局就绪

验证#

28 项全过，含 MISSING != ZERO 六条：连续=1 段 · 中间缺失=2 段 · 两段有真实间隔（381px） · 中间是 0 仍 1 段 · 全缺失不崩 · 末点缺失不画圆点。

另：aria-hidden 9/9 · role=img 0 个 · axe 0 违规 / 19 通过。

两个判别力验证： ① 复现"类名不一致"那个真 bug ⇒ 8 项 FAIL ② 注入"空值丢弃"老写法 ⇒ 3 项 FAIL
