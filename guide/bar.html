🔴 四条铁律#

#铁律落地在哪
一超量程必须被容器裁剪CSS 侧 overflow: hidden（JS 不参与）
二标注不得覆盖数据（≤ 4 个）markLabel() 只标关键点
三量程必须显式声明max 是必填参数，无默认值
铁门禁要能证伪05-audit/chart-check.js 覆盖本组件

铁律一：为什么两道裁剪都不能删#

.bar    { overflow: hidden; }   /* 第二道：防穿透到别的卡片 */
.bar__svg { overflow: hidden; } /* 根因：裁掉超出 viewBox 的部分 */

关键在 overflow 的默认值：SVG 的 overflow 默认是 visible，不是 hidden （canvas 才是默认 hidden）—— 与 HTML 的直觉相反。一根高度算出 400px、viewBox 只有 200px 的柱子会照原样画到外面。

⚠️ 但只裁剪是止损不是解决：被裁的那根看起来像"到顶了"。所以 JS 侧同时给出 data-clipped 标记 + .bar__note 文字说明。

铁律三：max 必填，因为自动适配是最隐蔽的谎报#

一个 400 的异常值 + 30 个 0.35 的常态值，若 Y 轴自适应到 400 ⇒ 所有常态值被压成一条贴底的直线 ⇒ 读者会得出「这些天完全没有变化」的错误结论。

所以 opt.max 没有默认值——不声明就是 bug，构造函数直接要求你回答。

铁律二：只标关键点#

标数字的位置会压在柱子上、彼此重叠（右下角糊成一团）。所以默认只标 4 个，其余靠 Y 轴刻度读。

启用#

const chart = Bar.draw({
  host: 元素,                        // 会自动清空
  series: [{ name: '成交', values: [120, 90, 150] },
           { name: '挂单', values: [30, 40, 20] }],
  max: 200,                          // 🔴 必填
  mode: 'stack',                     // 'stack'（默认）| 'group'
  labels: ['09-01', '09-02', '09-03'],
  threshold: 100,                    // 可选：画一条虚线
  height: 180,
  note: '…',
  legend: true,                      // 默认：系列 ≥2 且都有名字时自动出
});

返回 { el, clipped, mode, tops, legend, destroy() } —— clipped 是被裁的类目下标，tops 是每列合计/最高值。

🔴 堆叠 vs 分组：语义必须显式选择#

原实现的 base 数组在每个系列开始时被重置，且所有系列的柱用同一横坐标与同一柱宽 ⇒ 多系列不是堆叠，是后画的盖住先画的。它自称堆叠，实际重叠。

现在：base 提到系列循环外累计；堆叠宽度与分组宽度分开算。判据直接断言几何关系：多段柱首尾相接、重叠 0。

类名#

类用途
.bar / .bar__svg根 / SVG
.bar__bar + .bar__s0….bar__s4柱体 + 5 个分类色
.bar__grid / .bar__ytick / .bar__xlabel网格 / Y 刻度 / X 标签
.bar__label / --max / --clip标注（铁律二）
.bar__threshold阈值线
.bar__legend / __legend-item / __legend-swatch图例
.bar__note脚注（说明截断了什么）

超过 5 个系列请自己给 series[i].cls —— 颜色循环会造成误读。
