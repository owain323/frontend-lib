列定义（示例页里的用法）#

var COLS = [
  { key: 'revenue',   label: '营业收入', format: 'currency',       precision: 0, unit: '万元' },
  { key: 'margin',    label: '毛利率',   format: 'percent',        precision: 1 },
  { key: 'change',    label: '同比',     format: 'signed-percent', precision: 1 },
  { key: 'temp',      label: '温度',     format: 'decimal',        precision: 2, unit: '°C' }
];
format输入 → 显示正数加 +？
text原样—
integer1505600 → 1,505,600否
decimal0.25 → 0.25（绝不乘 100）否
currency1505600 → 1,505,600（金额）否
percent0.854 → 85.4%（输入是比例）否
signed-percent0.163 → +16.3% / -0.008 → −0.8%是

两条硬规则：

  1. 不按数值大小推断语义。0.25 是比例还是普通测量值，只能由列定义说，不能靠「小于 1 就乘以 100」。示例页第 4 节就是这条的自证。
  2. 正负号只按列语义。营收、成本、毛利率这类「量」的正数没有 +；只有 signed-*（同比/变化量）才加。负数一律用真减号 −（不是连字符 -）。

无障碍#

  • 数据表用 <th scope="col"> / <th scope="row">；多级表头第一层用 scope="colgroup"。复杂表格可用 id + headers 建立显式关联（本示例未用到，但结构支持）。
  • 排序状态放在 <th aria-sort="ascending|descending">，不是放在按钮上。
  • 正负不只靠颜色：颜色之外还有 + / − 符号（WCAG 1.4.1）。
  • 粘性表头的 z-index 走令牌；border-collapse: separate 是 sticky 生效的前提。

已知限制#

  • 不做虚拟滚动。行数上限交给调用方（> 200 行请配合分页）。
  • 排序 / 筛选 / 分页行为不与样式层捆绑 —— 需要时由调用方接自己的数据层。
  • 单位默认标在列头，不是每格重复（一列 20 个「万元」只会增加噪音）。若某列确需逐格带单位，调用方自行在格式化时拼接。

🔴 单位的写法：列名 +（单位），括号不能省#

✅ 抗拉强度 (MPa)     伸长率 (%)     时效 (100 °C)
❌ 抗拉强度 MPa       伸长率 %       时效 100 °C

这不是审美选择，是学科规范要求，五处权威口径一致：

来源要求
GB/T 7713.2-2022《学术论文编写规则》同时用量与单位表示时，采用「量的符号或名称/单位符号」的标准化形式
CY/T 170—2019《学术出版规范 表格》表头用「量的名称或符号/单位符号」；且表身单元格内不宜带单位
Science Author Guidelinesevery column should have a heading, followed by a unit of measure (if any) in parentheses
IEEE Standards Style Manual 14.3.1units shall be provided in parentheses, or preceded by a solidus（E (V) / E/V）

另外两条同源要求，本组件一并遵守：

  • 同栏单位不得变化（IEEE：不得把 Ω 与 MΩ 混用、mm 与 cm 混用）
  • 表身单元格内不带单位——只在列头标一次

为什么括号和同字号都很重要#

  • 括号：它把"列名"与"单位"在语法上分成两截。裸写 抗拉强度 MPa 读起来是两个并列的词，读者要停下来判断哪个是量名。
  • 同字号（font-size: inherit）：单位若比列名小一号，视觉上就成了 "另一行的小注"而不是"这一列的量纲"。规范里单位与列名同字号，只用括号（或可选斜体）区分即可。

.table__unit 自带 margin-inline-start，所以源码里写 <span class="table__unit">MPa</span> 渲染出来就是 抗拉强度 (MPa) —— 组件负责加括号，不要求每个调用方记得加（要求调用方做，迟早漏一处）。

配色：与本库 list 的约定不同（故意的，不是笔误）#

组件类名约定
tablenum--pos / num--neg会计约定：正 = 绿、负 = 红（负数即"红字"）
listlist__value--up / --down市场约定：涨 = 红、跌 = 绿（A 股惯例）

两种约定并存不是笔误，是因为两处的数是两种东西：

  • 表格里多是量（营收、毛利率、净利润）—— 负数是"红字"，会计惯例；
  • 列表里多是涨跌（涨跌幅、日变动）—— A 股惯例是涨红跌绿。

涨跌幅放进表格：解题方式（0.12.1 已定）#

把「涨跌幅」这一列塞进 table 时，两种约定会打架 —— 负的涨跌幅被渲染成红色，读者第一眼读成"涨"。这个问题曾经挂在 README 里写「目前没有解」，现在有了，而且不是当初列的两个候选之一：

市场涨跌不进 table 的颜色体系，而是嵌 delta 原子。

<td class="num"><span class="delta delta--up">3.21%</span></td>
<td class="num"><span class="delta delta--down">1.05%</span></td>
<td class="num"><span class="delta delta--flat">0.00%</span></td>
num--pos / num--neg嵌 delta
语义会计正负（多了 / 少了）市场涨跌（涨了 / 跌了）
颜色来源--success / --danger--dir-up / --dir-down
随 [data-market] 切换不切切
符号::before 的 + / −delta 自己的 + / − / 无

为什么否掉当初那两个候选：

  • num--up / num--down 会让 table 有四组颜色类，调用方每次都要记"这列用哪组"；
  • data-polarity="market" 是把语义塞进一个属性，表格得替数据判断"这列是涨跌"，而它并不知道 —— 调用方才知道。

⇒ 方向是独立语义，所以它就该是独立原子。表格只负责对齐（td.num），不负责判色。

⚠️ 不要两套一起用：<td class="num num--pos"><span class="delta delta--up"> 会让同一格同时受两套颜色支配，谁赢取决于选择器权重 —— 那是最难查的一类 bug。 table-check 的判据 ⑬ 会挡住给 table.css 添 num--up / num--down 的做法。

零值：两边都不许有符号（0.12.1 修，E145）#

format: 'signed-percent' 的正号由类名触发，而旧实现判的是 v < 0 ⇒ v === 0 落进 else 分支得到 num--pos，渲染成「+0.0%」—— 一个没变化的数被念成"涨了"。四舍五入处同样复现：0.0004 在 1 位精度下也印成「+0.0%」。

⇒ 规则只有一条：符号必须跟打印出来的数字同号。先算出将要打印的数值，再按它定符号；等于 0 既不加 + 也不加 − （这与 delta--flat 是同一个契约）。table-check 判据 ⑫ 守着它，并且要求页面上必须存在零值样本 —— 删掉零值行不能算通过。

反例#

  • ❌ 靠数值大小猜语义 —— 不能用"小于 1 就乘 100"。0.25 是比例还是普通测量值，只能由列定义的 format 说
  • ❌ 给"量"的正数加 + —— 营收、成本、毛利率这类量没有 +；只有 signed-percent 这类"变化量"才加。满屏 + 会让读者以为每个数都在变
  • ❌ 负数用连字符 - —— 用真减号 −；连字符在等宽数字里对不齐，也容易被当成项目符号
  • ❌ 排序状态放在按钮上 —— 要放 <th aria-sort="ascending|descending">；放在按钮上读屏不会报告"这一列正按什么排序"
  • ❌ 正负只靠红绿 —— 颜色之外必须有 + / − 符号（WCAG 1.4.1）
  • ❌ 粘性表头配 border-collapse: collapse —— separate 是 sticky 生效的前提，用 collapse 表头不会粘住
  • ❌ 拿它当虚拟滚动表格用 —— 本组件不做虚拟滚动；超过 200 行请配分页
  • ❌ 给表格再加一套「市场涨跌」的颜色类 —— 那是第三组方向类，加上会计的正负就是四组；市场涨跌嵌 delta（判据 ⑬ 会红）
  • ❌ 零值带 + —— 「+0.0%」= 把持平念成上涨；先算打印值再定符号（判据 ⑫ 会红）
