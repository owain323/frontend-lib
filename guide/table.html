列定义（示例页里的用法）#

var COLS = [
  { key: 'revenue',   label: '营业收入', format: 'currency',       precision: 0, unit: '万元' },
  { key: 'margin',    label: '毛利率',   format: 'percent',        precision: 1 },
  { key: 'change',    label: '同比',     format: 'signed-percent', precision: 1 },
  { key: 'temp',      label: '温度',     format: 'decimal',        precision: 2, unit: '°C' }
];
format输入 → 显示正数加 +？
text原样—
integer1505600 → 1,505,600否
decimal0.25 → 0.25（绝不乘 100）否
currency1505600 → 1,505,600（金额）否
percent0.854 → 85.4%（输入是比例）否
signed-percent0.163 → +16.3% / -0.008 → −0.8%是

两条硬规则：

  1. 不按数值大小推断语义。0.25 是比例还是普通测量值，只能由列定义说，不能靠「小于 1 就乘以 100」。示例页第 4 节就是这条的自证。
  2. 正负号只按列语义。营收、成本、毛利率这类「量」的正数没有 +；只有 signed-*（同比/变化量）才加。负数一律用真减号 −（不是连字符 -）。

无障碍#

  • 数据表用 <th scope="col"> / <th scope="row">；多级表头第一层用 scope="colgroup"。复杂表格可用 id + headers 建立显式关联（本示例未用到，但结构支持）。
  • 排序状态放在 <th aria-sort="ascending|descending">，不是放在按钮上。
  • 正负不只靠颜色：颜色之外还有 + / − 符号（WCAG 1.4.1）。
  • 粘性表头的 z-index 走令牌；border-collapse: separate 是 sticky 生效的前提。

已知限制#

  • 不做虚拟滚动。行数上限交给调用方（> 200 行请配合分页）。
  • 排序 / 筛选 / 分页行为不与样式层捆绑 —— 需要时由调用方接自己的数据层。
  • 单位默认标在列头，不是每格重复（一列 20 个「万元」只会增加噪音）。若某列确需逐格带单位，调用方自行在格式化时拼接。

🔴 单位的写法：列名 +（单位），括号不能省#

✅ 抗拉强度 (MPa)     伸长率 (%)     时效 (100 °C)
❌ 抗拉强度 MPa       伸长率 %       时效 100 °C

这不是审美选择，是学科规范要求，五处权威口径一致：

来源要求
GB/T 7713.2-2022《学术论文编写规则》同时用量与单位表示时，采用「量的符号或名称/单位符号」的标准化形式
CY/T 170—2019《学术出版规范 表格》表头用「量的名称或符号/单位符号」；且表身单元格内不宜带单位
Science Author Guidelinesevery column should have a heading, followed by a unit of measure (if any) in parentheses
IEEE Standards Style Manual 14.3.1units shall be provided in parentheses, or preceded by a solidus（E (V) / E/V）

另外两条同源要求，本组件一并遵守：

  • 同栏单位不得变化（IEEE：不得把 Ω 与 MΩ 混用、mm 与 cm 混用）
  • 表身单元格内不带单位——只在列头标一次

为什么括号和同字号都很重要#

  • 括号：它把"列名"与"单位"在语法上分成两截。裸写 抗拉强度 MPa 读起来是两个并列的词，读者要停下来判断哪个是量名。
  • 同字号（font-size: inherit）：单位若比列名小一号，视觉上就成了 "另一行的小注"而不是"这一列的量纲"。规范里单位与列名同字号，只用括号（或可选斜体）区分即可。

.table__unit 自带 margin-inline-start，所以源码里写 <span class="table__unit">MPa</span> 渲染出来就是 抗拉强度 (MPa) —— 组件负责加括号，不要求每个调用方记得加（要求调用方做，迟早漏一处）。
