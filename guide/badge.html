badge · 状态标记

状态标签：计数、分类、结果标记

  • 02-primitives/badge/demo.html
  • 02-primitives/badge/badge.css

承载一个短状态词（"已披露""已停牌""审计中"）。

类#

类作用
.badge基础（不带变体时是中性色）
.badge--neutral中性：草稿 / 归档 / 草稿态
.badge--success成功 / 已披露
.badge--warning警告 / 审计中
.badge--danger危险 / 已停牌
.badge--info信息 / 待复核
.badge--lg较大一档（13px）
.badge--clickable可点 —— 必须配合 <button> 或 <a>

用法#

<!-- 不可点（默认） -->
<span class="badge badge--success">已披露</span>

<!-- 可点：语义由元素承担，样式照抄 .badge -->
<button class="badge badge--info badge--clickable">待复核</button>

三条硬规矩#

1. 不可点就别用 button。 要能点必须用 <button> 或 <a> —— div + onclick 对读屏是「没有角色的按钮」：读不出能点，键盘也 Tab 不到。

2. 一定要有文字。 WCAG 1.4.1 要求不能只靠颜色区分。本组件的颜色是冗余线索，不是唯一编码 —— 去掉颜色也必须能读懂。

3. 不要数字角标。 badge 是"状态词"，不是"数字气泡"。

为什么是「淡底 + 深字」#

小字号（11–12px）在饱和底上白字对比度普遍不够。本库五组实测：

变体浅色暗色
--neutral6.7610.59
--success5.585.92
--danger4.825.37
--warning5.296.05
--info6.015.25

全部 ≥ 4.5 ⇒ 不需要为 badge 单独调一套色（省一次决策，也少一套漂移风险）。

反例的真实数字：暗色下白字在 --success 上只有 2.72:1（浅色是 6.39 达标）—— 看浅色时完全发现不了这个失效。这就是为什么每组都要两套都算。

两档尺寸#

出现第三档说明信息密度没规划好 —— 与 card 的判断标准一致。

强制高对比模式#

@media (forced-colors: active) 下边框改用 currentColor —— 靠边框保住边界，不靠底色。这一段本机无法验证（需系统级开关）。

尺寸#

高度 24px（默认）· 字号 12px —— 达 WCAG 2.2 的 24×24 最小目标。

验证#

  • component-contrast.py：5 组字/底组合两套配色全过
  • a11y-scan：本 demo axe 0 违规 / 16 条通过
