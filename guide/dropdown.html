dropdown · 下拉菜单

下拉菜单

  • 03-patterns/dropdown/demo.html
  • 03-patterns/dropdown/dropdown.css
  • 03-patterns/dropdown/dropdown.js

依据 APG（ARIA Authoring Practices）Menu Button 模式。

🔴 APG 的四条键盘契约（缺一条就不算合规）#

键行为
↑ ↓在项之间移动
Esc关闭，并把焦点还给按钮
Tab关闭菜单（焦点移到下一个元素）
Enter / Space激活当前项

⚠️ 另有两条容易漏的#

  • 关闭后焦点必须归位 —— 不归位，键盘用户在页面里迷路
  • 菜单项命中区 ≥ 44px —— 密集列表也必须够大（WCAG 2.5.5AAA）

结构#

⚠️ 类名前缀是 dd__，不是 dropdown__；标记是 data-dd-*。

<div class="dd">
  <button class="dd__btn" data-dd-btn aria-haspopup="menu" aria-expanded="false">
    <span>操作</span><span class="dd__caret" aria-hidden="true"></span>
  </button>
  <div class="dd__menu" data-dd-menu role="menu">
    <button class="dd__item" role="menuitem" data-value="edit">编辑</button>
    <hr class="dd__sep" data-dd-sep role="separator">
    <button class="dd__item" role="menuitem" data-value="del">删除</button>
  </div>
</div>
部件说明
.dd根
.dd__btn / [data-dd-btn]触发按钮
.dd__menu / [data-dd-menu]菜单本体，必需
.dd__item菜单项，带 data-value
.dd__sep / [data-dd-sep]分隔线
.dd__check多选勾选位
.dd--end菜单右对齐

启用#

const dd = Dropdown.create(元素);
  • [data-dd-btn] 找不到时退回第一个 <button>（省事的写法也能跑）
  • [data-dd-menu] 找不到 → 直接抛错

🔴 role="menu" 要么全设要么全不设#

// APG：菜单要么全 aria-hidden，要么全不设 —— 不能半吊子
menu.setAttribute('role', 'menu');

aria-hidden 打了一半在个别项上，读屏会读到一半就断掉。

状态写在 DOM 属性上#

data-state / data-value，不用 class 切换 —— 这是全库 INVARIANT I-8 （状态必须活在 DOM 属性上），也是门禁会查的东西。

成熟度：beta（两条行为债，如实列出）#

债现在的后果
focus-return:manual关闭后归位是手写的，不是统一机制
typeahead:gap没有类型搜索 —— APG 的 Menu Button 不硬性要求，但列表长时体验缺失

反例#

  • ❌ 菜单里一部分项 aria-hidden、一部分不设 —— APG 要求全设或全不设。半吊子会让读屏报"1 项中的 0 项"这种不可理解的计数
  • ❌ 禁用项不给 tabindex="-1" —— Tab 会停在点不动的项上，用户以为菜单坏了
  • ❌ Esc 关闭后焦点不还给 dd__btn —— 焦点掉到 <body>，键盘用户要从页面开头重新 Tab（APG 明确要求归还）
  • ❌ 给某个 dd__item 设 tabindex="0" —— role="menu" 靠方向键步进，多一个 0 就多出一个 Tab 停靠点，整个菜单的导航模型就混了
  • ❌ 先写 aria-controls 再确保 dd__menu 有 id —— 顺序反了会引用空字符串，读屏拿不到"这个按钮控制哪个菜单"（dropdown.js 里为此调过顺序）
  • ❌ 用 opacity: 0 或 visibility 隐藏 dd__menu —— 关闭态要用 hidden：它同时移出无障碍树并不可聚焦，另两种做法都还留着 Tab 停靠点
